## 1. Ключевые выводы (коротко)

1. **Qalta — только iOS** [Факт]. В Google Play её нет, на сайте заявлены iPhone, Mac и Vision Pro. В мастер-промпте Qalta описана как iOS + Android, это нужно поправить. **Android-аудитория Казахстана у этого конкурента не охвачена** [Вывод].
2. **Qalta не полностью локальная** [Факт]. Личные данные хранятся в SQLite на устройстве, бэкап идёт в iCloud. Голос и фото отправляются через бэкенд Qalta в OpenAI. Для AI-функций нужен вход через Apple или Google. Пользователи прямо спрашивают: зачем вход, если всё локально.
3. **Самая частая негативная тема у Qalta — монетизация** [Вывод]. Её упоминают около 16 из 53 прочитанных отзывов. Претензии: лимит около 150 операций в бесплатной версии даже для ручного ввода, нет пробного периода, нет разовой покупки, нет тарифа без AI.
4. **Ни один из изученных конкурентов не делает то, что задумано в U-Assistant** [Вывод]: голос → черновики **разных типов** (задача + расход + заметка) → обязательное подтверждение → сохранение **без сервера**. Самый близкий аналог — Todoist Ramble, но он облачный (Gemini) и создаёт только задачи.
5. **Связки «финансы ↔ задачи ↔ цели ↔ календарь» нет ни у кого** из рассмотренных [Вывод]. Финансовые трекеры не знают о задачах, планировщики не знают о деньгах.
6. **Модель переводов между своими счетами у лучших приложений одинаковая** [Вывод]: пара связанных записей, которые не входят в доходы и расходы. Перевод на счёт «только отслеживать» считается расходом.
7. **Потеря данных при переустановке — повторяющаяся жалоба локальных приложений** [Вывод]: Monefy, 3 из 34 видимых отзывов. Для local-only продукта напоминание о внешнем бэкапе обязательно.
8. **Перегрузка — главный риск приложений «всё-в-одном»** [Вывод]. Notion на мобильных медленный и не умеет быстро захватывать мысль (4+ источника). TickTick прячет функции за переключателями.

## 3. Qalta — подробный разбор

> Основной референс по мастер-промпту. Прочитано **53 текстовых отзыва App Store**: KZ 10, RU 10, BY 10, US 7, UA 6, UZ 4, KG 3. Период — с декабря 2025 по октябрь 2026.

### 3.1 Профиль
- [Факт] «Qalta: Budget, Expense Tracker», разработчик Daniel Tokkozhin, соло-разработчик из Казахстана. Первый релиз — 15.12.2025, версия 2.0.0 — 13 октября 2026. Требуется iOS 16.4+. Рейтинг в KZ — 4.7 по 99 оценкам (проверено вручную).
- [Факт] Стек по данным TrustMRR: Expo/React Native, OpenAI, RevenueCat, Supabase, SQLite. MRR около $2.1k, ~499 активных подписок.
- [Факт] 26 версий за ~10 месяцев. Многие запросы из отзывов закрыты за 2–8 месяцев.
- [Факт] Рост шёл через вирусные ветки в Threads.

### 3.2 Сильные стороны
- **Скорость ввода — главный козырь.** Слоган — «Track money at the speed of speech». Способы записи без открытия формы: голос с несколькими операциями в одной фразе, скан чеков и PDF/CSV-выписок, автозапись после Apple Pay и из банковских push через Shortcuts, Back Tap/Action Button, виджеты. Ручной ввод ускоряют подсказки, запоминание последнего счёта и свайп доход/расход. [Факт]
- **Визуал** — главный повод для похвалы, около 33 отзывов. [Вывод]
- Мультивалюта с ручной правкой курса, кастомные валюты, группы и скрытие счетов. [Факт]
- Импорт из 8+ конкурентов (YNAB, Spendee, Monefy, ZenMoney, CoinKeeper…) снижает барьер переезда. [Факт]
- 14 языков, включая русский и казахский. [Факт]

### 3.3 Слабые стороны и спорные решения
| Наблюдение | Тип | Чем это поможет U-Assistant |
|---|---|---|
| Только iOS | [Факт] | Android + iOS с первого дня |
| Лимит ~150 **ручных** операций в бесплатной версии | [Факт, из ответов разработчика] | Базовый учёт без лимитов |
| Нет пробного периода и разовой покупки (просят в UA ×2, US) | [Факт] | Учесть, если когда-нибудь будет монетизация |
| Обязательный вход ради AI-лимитов | [Факт] | Работа без аккаунта, голос без внешних AI |
| Голос и сканы уходят в OpenAI | [Факт] | Локальный разбор на правилах |
| Нет PIN или Face ID (просят RU, US); выпуск не подтверждён | [Факт/н/п] | Блокировка приложения в v1 |
| Перевод можно учитывать как доход или расход | [Факт] | Строгая модель: перевод ≠ доход/расход; на счёт «только отслеживать» — расход |
| Автоматизации требуют ручной настройки Shortcuts | [Вывод] | Простые точки входа без настройки |
| Синхронизации личных данных между своими устройствами нет, перенос на новый телефон вызывает вопросы | [Факт] | Понятный мастер переноса через файл |
| Ответ разработчика на негативный отзыв с обвинением автора | [Факт] | Репутационный урок для поддержки |

### 3.5 Что проверить не удалось
Структура вкладок, актуальные лимиты бесплатной версии (известны только из ответов разработчика за декабрь–апрель), наличие код-пароля в 2.0.0, звёзды отдельных отзывов.

| **Wallet** | Шаблоны операций; разовые и повторяющиеся бюджеты | Зависимость от облака и банков |
| **YNAB** | Идея «доступно к распределению» как опция | Полный zero-based для массового пользователя; одна валюта на бюджет |

| **Actual Budget** | Флаг счёта «в бюджете / только отслеживать»; набор отчётов (Cash Flow, Net Worth, сравнение периодов); предупреждение о невосстановимости при E2E | Отсутствие мультивалюты и нативного мобильного приложения |

**Переход от графика к операциям (drill-down).** Ни в одном официальном источнике это прямо не описано, кроме упоминания drill-down по подкатегориям у Qalta. Делаем обязательным [П].

## 7. Предварительные определения понятий

На основе Things, Todoist и TickTick [Вывод]. Окончательно фиксируются на этапе требований.

| Понятие | Определение | Хранится как | Пример |
|---|---|---|---|
| **Цель** | Желаемый результат с измеримым критерием (если применим). Сама не «выполняется», у неё есть прогресс | Сущность `Goal` | «Накопить 500 000 ₸ на ноутбук к марту», «Защитить диплом» |
| **Проект** | Конечный набор задач с понятным «готово». Может вести к цели | Сущность `Project` | «Подготовить диплом к предзащите» |
| **Задача** | Одно конкретное действие. Может иметь дату, дедлайн, повтор, подзадачи | Сущность `Task` | «Позвонить преподавателю по поводу диплома» |
| **План** | Расписание: какие задачи и когда (день или неделя). **Это представление, а не отдельная запись** | Вид (экран «Сегодня», календарь) | «План на завтра» |
| **Привычка** | Регулярное действие со статистикой выполнения (кандидат на позже) | Сущность `Habit` (позже) | «Читать 20 минут» |

> Открытый вопрос: в мастер-промпте «Планы и проекты» стоят рядом. Предлагаю не делать «план» отдельной сущностью. Если вам нужен именно хранимый «план» (например, «план на неделю» с заметкой), это нужно решить на этапе требований.

## 8. Продуктовые гипотезы для этапа требований

| # | Гипотеза | Как проверить |
|---|---|---|
| H1 | Главная ценность для пользователя — не голос, а **быстрая запись любым способом** и связи между модулями | Собственное использование прототипа: какие способы ввода реально применяются |
| H2 | Экран «Сегодня» (задачи по времени + предстоящие платежи + остаток бюджета) снимает потребность в отдельном таймлайне в v1 | Прототип экрана, проверка на перегруженность |
| H3 | Правилового разбора хватает для 80% типовых русских фраз (даты, суммы, «напомни», «потратил») | Корпус 100–200 реальных фраз, автотесты парсера |
| H4 | Пользователь готов к ручным курсам, если валютных счетов немного | Собственное использование |
| H5 | Напоминание о внешнем бэкапе раз в N дней не раздражает | Настраиваемая периодичность, проверка на себе |
| H6 | Связка «цель накоплений ↔ жизненная цель ↔ задачи» — ключевое отличие от Qalta и Cashew | Пользовательские сценарии на этапе UX |
