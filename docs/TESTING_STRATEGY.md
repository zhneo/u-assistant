# U-Assistant — стратегия тестирования и качества (этап 6б)

> Статус: **черновик на согласование**. Дата: 23.10.2026.
> Основание: мастер-промпт §16 и §20 (правила 7, 9, 10); REQUIREMENTS §7 (NFR) и §9 (AC-01…26); ARCHITECTURE §18–19; DATABASE §5; BACKUP_AND_RESTORE §13; VOICE_INPUT §9.
> Цель документа: до начала разработки договориться, **что, где, чем и когда** проверяется, и что значит «функция готова».

---

## 1. Принципы
1. **Тесты пишутся вместе с кодом**, а не после. Для финансовых формул, повторений, разбора голоса и формата бэкапа — сначала тест по правилу из документации, потом реализация.
2. **Источник ожиданий — документы**, а не код:
   - финансы — REQUIREMENTS §6;
   - инварианты — DATABASE §5;
   - сценарии — AC-01…26;
   - голос — корпус VOICE_INPUT §9.2.
3. **Большинство тестов запускается на Windows и в CI без устройства.** Это прямое следствие отсутствия Mac (D-003) и архитектуры с `core` на чистом Dart (D-021).
4. **«Протестировано» означает, что тесты запущены и прошли** (мастер-промпт §20, правило 9). В отчётах о работе указывается команда и результат.
5. **Ошибка → тест.** Каждая найденная ошибка сначала воспроизводится тестом, потом исправляется.

## 2. Пирамида тестов

```
                ▲  Ручные проверки на устройствах (iPhone, Android-эмулятор) — чек-лист вехи
               ▲▲▲  Интеграционные сценарии (integration_test, Android-эмулятор)
             ▲▲▲▲▲▲▲  Widget- и golden-тесты экранов (CI)
         ▲▲▲▲▲▲▲▲▲▲▲▲▲  Сценарии + репозитории + миграции на базе в памяти (CI)
   ▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲  Unit-тесты core: деньги, финансы, повторения, голос, бэкап (CI)
```

| Уровень | Что проверяет | Инструменты | Где | Скорость |
|---|---|---|---|---|
| **Unit (`core`)** | Чистые правила | `package:test` | Windows, CI | мс |
| **Репозитории** | Запросы, агрегаты, инварианты, триггеры | drift + `NativeDatabase.memory()` | Windows, CI | мс–с |
| **Миграции** | Старая схема с данными → новая | `drift_dev` (сгенерированные проверки + снимки `drift_schemas/`) | Windows, CI | с |
| **Сценарии** | Use cases с настоящей базой в памяти и фейками платформы | `test` + фейки (`FakeClock`, `FakeNotifications`, `FakeSpeech`, `FakeFiles`, `FakeSecureStorage`) | Windows, CI | с |
| **Widget** | Экраны и компоненты: состояния, нажатия, доступность, темы | `flutter_test`, `ProviderScope(overrides)` | Windows, CI | с |
| **Golden** | Визуальная регрессия ключевых экранов | `matchesGoldenFile` | **Только CI на Linux** (снимки зависят от ОС) | с |
| **Интеграционные** | Сквозные пути на реальной сборке | `integration_test` | Android-эмулятор (локально, позже CI) | мин |
| **Ручные** | Речь, уведомления, Keychain, биометрия, системные диалоги, жесты | Чек-лист §9 | iPhone (сборка Codemagic через Sideloadly), эмулятор Android | — |

> **Простыми словами.** Внизу пирамиды — тысячи быстрых проверок правил («перевод не меняет расходы»), они бегут за секунды на любом компьютере. Наверху — немного медленных проверок на телефоне, которые ловят то, что видно только на устройстве: пришло ли уведомление, работает ли микрофон.

## 3. Что тестируется на каждом уровне (по модулям)

### 3.1 Финансы (`core/money`, `core/finance`, money-репозитории)
| Тема | Тесты |
|---|---|
| `Money` | Арифметика только в одной валюте; разрядность ISO 4217 (KZT 2, JPY 0, KWD 3); форматирование `1 234 567,89 ₸`; запрет `double` |
| Конвертация | Округление «половина к чётному» на пограничных значениях (…,5); курс как `Decimal`; фиксация `amount_base_minor` при записи |
| Баланс счёта (§6.2) | Все типы операций; плановые и удалённые не учитываются |
| Доходы и расходы (§6.4) | Переводы между `on_budget` не входят; `on_budget → tracking` = расход; возврат уменьшает категорию; корректировки и долги не входят |
| Бюджет (§6.6) | Подкатегории включаются; день начала месяца; прогноз с плановыми; перерасход |
| «Можно потратить» | Плановые расходы и доходы до конца периода |
| Долги (§6.7) | Остаток из движений; переплата; списание остатка |
| Накопления (§6.8) | Несколько счетов в разных валютах |
| Нет курса | Итог помечается «неполный», счёт не считается нулём |
| Импорт CSV | Разбор форматов, сопоставление, дубликаты, ошибка в строке → ничего не импортировано |
| Агрегаты репозитория | Суммы по дням и категориям совпадают с суммой списка операций (AC-20) на сгенерированных данных |

**Метод «двойного счёта»:** на генерированной базе (§6) итоги, посчитанные SQL-агрегатами репозитория, сравниваются с итогами, посчитанными чистой функцией `core` по тем же операциям. Расхождение = ошибка в одном из двух мест.

### 3.2 Задачи, повторения, привычки
- `RecurrenceEngine`:
  - все виды `rrule`: последний день месяца, 31-е в коротком месяце, 29 февраля, «второй вторник»;
  - режимы «по расписанию» и «от выполнения»;
  - пропуск, исключение «только этот раз», изменение правила, пауза, окончание серии;
  - следующий экземпляр всегда в будущем.
- Инвариант «один открытый экземпляр у серии» (DATABASE I5): двойной вызов «выполнить» создаёт ровно один следующий.
- Привычки: серии по расписанию «N раз в неделю», пауза не ломает серию.
- Перенос, массовые действия, корзина и восстановление со связями.

### 3.3 Напоминания и уведомления
| Тест | Уровень |
|---|---|
| `desiredOccurrences(window)` для всех видов напоминаний; лимит iOS 50 | Unit / сценарий |
| `reconcile()` идемпотентен: повторный вызов не меняет набор | Сценарий с `FakeNotifications` |
| Удаление задачи → уведомление отменено (AC-07); восстановление → снова запланировано | Сценарий |
| Выполнение повторяющейся → уведомление перенесено на следующий экземпляр (AC-08) | Сценарий |
| Смена часового пояса → пересчёт | Сценарий с `FakeClock` |
| Нет разрешения на точные будильники → неточный режим, статус на SCR-85 | Сценарий + ручной (эмулятор Android 14) |
| Уведомление реально приходит в нужное время (iPhone, эмулятор) | Ручной чек-лист |
| Действия «Выполнено / Отложить» из уведомления | Ручной + интеграционный (Android) |

### 3.4 Голосовой ввод
Полностью — VOICE_INPUT §9: тесты каждого этапа, корпус фраз с метрикой ≥ 80% и **нулём выдуманных полей**, сохранение (AC-04, AC-05, AC-06, AC-26).

### 3.5 Бэкап, экспорт, восстановление
Полностью — BACKUP_AND_RESTORE §13: круговой тест «бэкап → восстановление → сравнение всех таблиц» (AC-11), повреждённый файл (AC-12), новая версия (AC-13), неверный пароль (AC-14), прерывание на каждом шаге, нет места, ротация копий, миграция старой копии, перенос iPhone ↔ Android вручную.

### 3.6 Безопасность и приватность
- Логгер не пропускает пользовательские данные (AC-24): тест пытается залогировать операцию, задачу и черновик голоса.
- Ключ базы: создание, чтение, отсутствие → SCR-03 (с `FakeSecureStorage`).
- PIN: хеш, задержки после ошибок, сохранение счётчика при перезапуске.
- Манифест Android: скрипт CI проверяет, что нет разрешений сверх списка DATA_SECURITY §9 (в том числе `INTERNET`).

### 3.7 Миграции базы
- На каждую версию схемы — сгенерированный тест drift «vN → vN+1» и тест «v1 → текущая» на генерированных данных: все строки на месте, инварианты DATABASE §5 соблюдаются.
- Снимки схемы в репозитории; CI падает, если схема изменилась без новой версии и снимка.

### 3.8 Интерфейс
| Что | Как |
|---|---|
| Состояния экранов (пусто, загрузка, ошибка, частичные данные, нет разрешения) | Widget-тесты по пунктам «Состояния» UI_SPECIFICATION |
| Действия и переходы | Widget-тесты: нажатие → ожидаемый вызов сценария или маршрута |
| **Светлая и тёмная тема** | Каждый widget-тест ключевых экранов прогоняется в обеих темах; golden-снимки в обеих |
| **Размеры экранов** | Golden и widget на 3 размерах: 375×667 (iPhone SE), 430×932 (большой телефон), 820×1180 (планшет — «не ломается») |
| **Крупный шрифт** | `textScaler` 1,0 / 1,5 / 2,0: нет переполнений (`overflow` ловится как ошибка теста), сводки перестраиваются |
| **Доступность** | Встроенные проверки `flutter_test`: `androidTapTargetGuideline`, `iOSTapTargetGuideline`, `labeledTapTargetGuideline`, `textContrastGuideline` на ключевых экранах; наличие `Semantics` у графиков |
| Токены дизайн-системы | Unit-тест контраста пар цветов DESIGN_SYSTEM §2.1 (≥ 4,5:1 для смыслового текста) в обеих темах |
| Число нажатий в сценариях S1–S13 | Интеграционные тесты считают нажатия на ключевых путях S1, S3, S4, S6 |

Golden-тесты используют встроенный в тесты шрифт (Inter из ассетов тестов), иначе снимки будут отличаться между машинами [П].

### 3.9 Обработка ошибок
- Каждый вариант `AppFailure` → правильный текст (таблица в тесте `failure_messages`).
- Ошибка внутри многошаговой операции (перевод, голос, импорт, восстановление) → откат, база без частичных изменений: «ошибка одной операции не повреждает базу» (мастер-промпт §16).
- Глобальный перехват: исключение в контроллере → сообщение пользователю + запись в журнал, приложение не падает.

### 3.10 Производительность
| Метрика (NFR) | Как измеряется |
|---|---|
| PERF-01 Холодный запуск ≤ 2 с | `integration_test` + `traceAction` на эмуляторе (ориентир); на iPhone — вручную, профильная сборка |
| PERF-03 Прокрутка 10 000 операций | Профильная сборка, Flutter DevTools (кадры > 16 мс) |
| PERF-04 Аналитика на 50 000 операций ≤ 500 мс | Бенчмарк-тест репозитория на генерированной базе (Windows / CI) |
| PERF-05 Поиск ≤ 300 мс | Бенчмарк на генерированной базе |
| PERF-06 Бэкап 50 000 записей ≤ 5 / 10 с | Бенчмарк сценария бэкапа |
| Разбор фразы ≤ 50 мс | Бенчмарк `core/voice` |

Бенчмарки в CI сравниваются с порогом с запасом ×3 (машины CI медленнее и нестабильны); точные цифры — замер вручную перед вехой.

## 4. Критерии приёмки критических функций

Обязательные автоматические тесты. Их названия совпадают с ID для поиска.

| ID теста | Проверка | Уровень |
|---|---|---|
| AC-01 | Перевод между своими счетами не увеличивает доходы и расходы | Сценарий |
| AC-02 | Межвалютный перевод хранит обе суммы и курс | Сценарий |
| AC-03 | Перевод на счёт «только отслеживать» = расход | Сценарий |
| AC-04 | Подтверждённая голосовая запись сохраняется один раз (двойное нажатие) | Сценарий |
| AC-05 | Пример фразы из мастер-промпта → 3 правильных черновика | Unit (корпус) |
| AC-06 | Отменённая голосовая запись не попадает в базу | Сценарий |
| AC-07 | Удалённая задача не оставляет активного напоминания | Сценарий |
| AC-08…10 | Повторяющиеся задачи: выполнение, пропуск, «от выполнения» | Unit + сценарий |
| AC-11 | Восстановление из бэкапа не создаёт дубликаты и ничего не теряет | Интеграционный (база на диске) |
| AC-12…14 | Повреждённый, новый, неверный пароль | Unit |
| AC-15 | Ошибка в строке импорта → ничего не импортировано | Сценарий |
| AC-16, 17 | Нет курса; новый курс не меняет историю | Сценарий |
| AC-18 | Бюджет не учитывает переводы | Сценарий |
| AC-19 | Долг не является доходом или расходом | Сценарий |
| AC-20 | Сумма операций из графика = значение сегмента | Репозиторий (двойной счёт) |
| AC-21 | Повторный импорт CSV не создаёт дубликатов | Сценарий |
| AC-22 | Системный календарь не дублируется и не пишется в базу | Сценарий с фейком календаря + ручной |
| AC-23 | Офлайн-работа основных сценариев | Ручной (авиарежим) + интеграционный без сети |
| AC-24 | Логи без содержимого | Unit |
| AC-25 | Блокировка и скрытие содержимого | Widget + ручной |
| AC-26 | Ошибка сохранения голоса → текст и черновики на месте, частичных записей нет | Сценарий |
| TX-ATOMIC | Ошибка любой многошаговой операции не оставляет частичных изменений | Сценарий (параметризованный по всем таким операциям) |

## 6. Тестовые данные
- **Генератор «типичной базы»** (`app/test/fixtures/generator.dart`, детерминированный по зерну):
  - 3 года данных: 4 счёта в 2 валютах, ~15 000 операций с переводами, возвратами, долгами и регулярными платежами;
  - 5 000 задач с сериями;
  - 1 000 заметок;
  - удалённые записи.
  Масштаб ×3 для нагрузочных тестов (50 000 операций). Один генератор для тестов миграций, бэкапа, производительности и двойного счёта.
- **Фиксированная дата:** все тесты используют `FakeClock` (по умолчанию пятница, 23.10.2026, 14:00, Asia/Almaty), чтобы относительные даты не «плыли».
- **Никаких реальных данных владельца** в репозитории (DATA_SECURITY §13).

## 7. Фейки платформы
| Фейк | Подменяет | Позволяет проверить |
|---|---|---|
| `FakeClock` | Время и часовой пояс | Даты, повторы, смену пояса |
| `FakeNotifications` | `flutter_local_notifications` | Что запланировано и отменено; лимит 64; нет разрешения |
| `FakeSpeechRecognizer` | Распознавание | Все события и ошибки (VOICE_INPUT §2.1) |
| `FakeSecureStorage` | Keychain / Keystore | Ключ есть, нет, повреждён |
| `FakeFileSystem` / temp dir | Файлы | Нет места, ошибка записи, прерывание |
| `FakeCalendar` | Системный календарь | События, отзыв разрешения |
| `FakeBiometrics` | `local_auth` | Успех, отмена, недоступность |

Фейки реализуют те же интерфейсы `platform/`, что и настоящие адаптеры (ARCHITECTURE §1.3), поэтому сценарии не знают, с чем работают.

## 8. CI: обязательные проверки
На каждый push и pull request (GitHub Actions, ARCHITECTURE §19):
1. `dart format --set-exit-if-changed .`
2. `flutter analyze` — 0 ошибок и предупреждений.
3. Проверка запрещённых импортов (ARCHITECTURE §1.3) и разрешений манифеста (§3.6).
4. `dart test packages/core --coverage` + проверка порогов §5.
5. Корпус голоса с метрикой и проверкой «0 выдуманных полей».
6. `flutter test app` (unit, сценарии, widget).
7. Тесты миграций и проверка «схема изменилась без новой версии».
8. Golden-тесты (Linux).
9. Бенчмарки с мягкими порогами (предупреждение, не падение) [П].
10. Сборка Android debug APK.

**Слияние в `main` — только при зелёных проверках 1–8.**

Сборка iOS (Codemagic) — при слиянии в `main` и вручную перед проверкой на iPhone.

## 9. Ручные проверки на устройствах (чек-лист вехи)
Выполняются перед закрытием каждой вехи на iPhone (сборка Codemagic через Sideloadly) и на эмуляторе Android 14. Результат записывается в `docs/test-runs/M<n>.md`: дата, сборка, что прошло, что нет.

- [ ] Установка, онбординг, первый расход ≤ 30 с.
- [ ] Светлая, тёмная и системная тема; переключение на лету.
- [ ] Крупный шрифт (системная настройка) на ключевых экранах.
- [ ] VoiceOver (iPhone) и TalkBack (эмулятор): S1 и S4 проходят только диктором.
- [ ] Уведомление по расписанию приходит (через 2 минуты, приложение в фоне и закрыто); действие «Выполнено».
- [ ] Android 14: запрет точных будильников → неточный режим, статус на SCR-85.
- [ ] Голос: русский, режим «на устройстве» на iPhone; прерывание звонком (симулятор звонка недоступен — проверить сворачиванием).
- [ ] Блокировка: PIN, Face ID, автоблокировка, размытие в переключателе приложений.
- [ ] Бэкап: экспорт в «Файлы», восстановление на другом устройстве (iPhone ↔ эмулятор).
- [ ] Авиарежим: S1–S6, S8–S12 работают (AC-23).
- [ ] Перезагрузка телефона → уведомления восстановлены.
- [ ] Нет сетевых запросов приложения (Android: монитор сети эмулятора) [П].

**Ограничение:** поведение реальных Android-устройств с агрессивным энергосбережением (Xiaomi, Samsung) на эмуляторе не проверяется (D-009). Это отмечается в отчёте вехи как непроверенное.

## 10. Определение готовности функции (Definition of Done)
Функция считается готовой, когда:
1. Реализовано всё, что описано для неё в REQUIREMENTS и UI_SPECIFICATION, или отклонения записаны в DECISIONS.md.
2. Написаны и **запущены** тесты нужных уровней (§3), включая тесты её AC.
3. CI зелёный (§8).
4. Обе темы и крупный шрифт проверены widget- или golden-тестами.
5. Для функций с платформенной частью — пункт ручного чек-листа выполнен на iPhone и эмуляторе.
6. Обновлена документация, если поведение отличается от описанного.
7. В отчёте о работе указаны созданные и изменённые файлы, команды проверки и их фактический результат.

## 11. Работа с ошибками
- Ошибка записывается в GitHub Issues с шагами воспроизведения, ожидаемым и фактическим результатом, сборкой и устройством. Без пользовательских данных.
- Исправление: тест, который падает → исправление → тест проходит → ссылка на issue в коммите.
- Ошибки в финансах, бэкапе и потере данных — приоритет «блокирует выпуск».
