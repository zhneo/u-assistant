## 1. Концепция продукта

**Видение.** U-Assistant — личное мобильное приложение. В нём задачи, проекты, цели, привычки, деньги, заметки и календарь хранятся в одной локальной базе и связаны между собой. Записать что-либо можно за несколько секунд — вручную или голосом. Данные никуда не уходят без явного действия пользователя.

**Основной пользователь (v1).** Сам автор: студент или молодой специалист в Казахстане, ведёт деньги в тенге и иногда в другой валюте, совмещает учёбу или работу с личными делами, пользуется iPhone. Дальше продукт рассчитан на похожую аудиторию: 18–35 лет, русскоязычные, ценят приватность (см. решение D-004).

**Ценностное предложение.**
1. **Одно место вместо 4–6 приложений** и связи между записями: цель ↔ проект ↔ задачи ↔ накопления ↔ заметки.
2. **Быстрая запись:** расход за ≤ 3 нажатия; голосом — несколько записей разных типов за один раз, с проверкой перед сохранением.
3. **Приватность по умолчанию:** без регистрации, без сервера, база зашифрована, бэкап — файл под контролем пользователя.
4. **Честная финансовая аналитика:** переводы не искажают доходы и расходы, с любого графика можно перейти к исходным операциям.

**Не цели продукта.** Чат с ИИ. Совместная работа. Банковская синхронизация. Облачная синхронизация между устройствами (в v1). Замена полноценного календаря.

## 2. Термины

Термины обязательны для всех следующих документов и для кода.

| Термин | Определение |
|---|---|
| **Цель** (Goal) | Желаемый результат с критерием достижения. Сама не «выполняется» — у неё есть прогресс. Типы: *количественная* (целевое значение + единица), *накопительная* (целевая сумма + привязанные счета), *результатная* (прогресс по связанным проектам и задачам) |
| **Проект** (Project) | Конечный набор задач с понятным состоянием «готово». Может вести к цели |
| **Задача** (Task) | Одно конкретное действие. Может иметь подзадачи, дату выполнения, дедлайн, напоминания, повтор |
| **Подзадача** | Пункт-чек внутри задачи. Без своих дат и напоминаний [П] |
| **План** | **Не хранимая сущность**, а представление: экран «Сегодня», календарь, «Предстоящие». Строится из задач, привычек, напоминаний и плановых платежей с датами (решение D-007) |
| **Привычка** (Habit) | Регулярное действие с отметками выполнения и сериями. Не задача: не «завершается» и не переносится |
| **Напоминание** (Reminder) | Момент времени, когда ОС показывает уведомление о записи (задача, привычка, плановый платёж, долг) |
| **Правило повторения** (RecurringRule) | Описание периодичности (ежедневно, по дням недели, ежемесячно, каждые N…, до даты / N раз). Используется задачами, привычками, плановыми операциями |
| **Счёт** (Account) | Место, где лежат деньги: наличные, карта, банковский счёт, вклад, кредит. Имеет одну валюту и флаг «в бюджете / только отслеживать» |
| **Операция** (Transaction) | Изменение баланса счёта. Типы: *расход*, *доход*, *перевод*, *корректировка баланса*, *движение по долгу* |
| **Перевод** | Перемещение денег между своими счетами. Хранится как пара связанных записей и **не является ни доходом, ни расходом** (R1). Исключение — перевод на счёт «только отслеживать», см. §6 |
| **Плановая операция** | Будущая операция по правилу повторения или разовая. Не влияет на фактический баланс, пока её не подтвердили |
| **Категория** | Классификатор доходов и расходов. Двухуровневая: категория → подкатегория |
| **Бюджет** | Лимит расходов по одной или нескольким категориям за период |
| **Долг** (Debt) | Обязательство «мне должны» или «я должен» с остатком и историей движений |
| **Базовая валюта** | Валюта, в которой считаются общие итоги (по умолчанию KZT) |
| **Заметка** (Note) | Текст в упрощённом Markdown с тегами и ссылками на другие записи |
| **Тег** | Пользовательская метка, применимая к задачам, заметкам, проектам и операциям |
| **Связь** | Явная ссылка одной записи на другую (например, заметка → задача) |
| **Корзина** | Мягко удалённые записи, которые можно восстановить в течение срока хранения |
| **Резервная копия** (бэкап) | Полный снимок всех данных и настроек в одном файле. Используется для восстановления и переноса на другое устройство |
| **Экспорт данных** | Выгрузка части данных в открытом формате (CSV, Markdown). **Не бэкап**: из неё приложение нельзя полностью восстановить |
| **Голосовая сессия** | Один цикл «запись → распознанный текст → черновики → подтверждение» |
| **Черновик** | Предварительная запись, извлечённая из голоса. Не попадает в основные данные до подтверждения |

## 3. Объём и выпуски

### 3.1 Состав v1.0

По решениям D-005 и D-008 в v1.0 входят:
- задачи, проекты, цели, привычки;
- финансы: счета, операции, переводы, категории, мультивалюта, регулярные платежи, бюджеты, накопления, долги, аналитика, импорт и экспорт CSV;
- заметки;
- календарь, включая показ событий системного календаря;
- напоминания;
- история;
- голосовой ввод на русском;
- бэкап и восстановление;
- блокировка и шифрование;
- настройки.

### 3.2 Внутренние вехи v1.0 [П]

Состав v1.0 большой, а разработчик один. Чтобы приложением можно было **пользоваться самому как можно раньше**, v1.0 собирается вехами. Каждая веха — рабочая сборка на iPhone и Android. Подробно вехи раскрываются в ROADMAP на этапе 6–7.

| Веха | Содержание | Зачем в таком порядке |
|---|---|---|
| M1 Фундамент + финансы-ядро | Проект, тема, база, миграции, шифрование, счета, операции, переводы, категории, мультивалюта, быстрый ввод, список операций, поиск | Финансы — самый требовательный к точности модуль; модель денег должна быть правильной с первого дня |
| M2 Продуктивность | Задачи, подзадачи, проекты, цели, повторения, напоминания, экран «Сегодня» | Вместе с M1 даёт ежедневное использование |
| M3 Бэкап и безопасность | Автобэкап, экспорт и восстановление, пароль бэкапа, PIN и биометрия, корзина | **Нельзя пользоваться приложением «по-настоящему» без бэкапа**, поэтому это сразу после M2 |
| M4 Планирование денег | Регулярные платежи, бюджеты, накопления, долги, аналитика с переходом к операциям | — |
| M5 Заметки, календарь, история | Заметки, связи, календарь (месяц, неделя, день), системный календарь, журнал действий | — |
| M6 Голос | Распознавание, разбор, черновики, подтверждение | Самый рискованный модуль; к этому моменту стабильны все сущности, которые он создаёт |
| M7 Привычки, импорт CSV, полировка | Привычки, импорт CSV, доступность, производительность, подготовка к магазинам | — |

> Риск объёма (см. COMPETITOR_RESEARCH, риск 2) сохраняется. Если сроки поползут, первыми кандидатами на перенос в v1.1 станут привычки, импорт CSV и показ системного календаря — то есть то, что вы добавили сверх ядра.

## 6. Правила финансовых расчётов

Это нормативная часть: тесты финансовой логики пишутся по ней.

### 6.1 Представление сумм
- Сумма хранится как **целое число минимальных единиц** валюты (тиынов, центов) + код ISO 4217. Число дробных разрядов берётся из встроенной таблицы ISO 4217 (KZT — 2, JPY — 0, KWD — 3).
- Числа с плавающей точкой (`double`) для денег **запрещены** — в хранении, расчётах и передаче между слоями.
- Знак хранится явно через тип операции. Сумма в записи всегда ≥ 0, кроме корректировки баланса.

### 6.2 Баланс счёта
`Баланс(счёт) = начальный баланс + Σ доходы − Σ расходы + Σ входящие переводы − Σ исходящие переводы ± корректировки ± движения по долгам`
— только по **фактическим** (не плановым, не удалённым) операциям, в валюте счёта.

### 6.3 Общий баланс
- Сумма балансов счетов без флага «скрыть», пересчитанная в базовую валюту по **последнему введённому курсу** каждой валюты. Рядом показывается дата курса.
- Если курса нет — итог помечается как неполный (FR-FIN-16).
- Счета-кредиты входят с отрицательным балансом.

### 6.4 Доходы и расходы за период
- Учитываются только операции типов *доход* и *расход* с датой в периоде.
- **Не учитываются:** переводы между счетами «в бюджете», корректировки, движения по долгам, плановые операции.
- Перевод со счёта «в бюджете» на счёт «только отслеживать» считается **расходом** (категория обязательна). Обратный перевод считается **доходом**. Так ведут себя Actual и YNAB (R1).
- Возврат (FR-FIN-10) уменьшает расход своей категории, но не ниже нуля в отчёте по категории. Остаток показывается как доход.
- Пересчёт в базовую валюту — **по курсу, сохранённому в операции** на дату её ввода. Последующие изменения курса историю не меняют (R2).

### 6.5 Чистый поток
`Чистый поток = Доходы − Расходы` за период по правилам §6.4.

### 6.6 Бюджет
- `Потрачено = Σ расходов (в базовой валюте, §6.4) в категориях бюджета, включая подкатегории, за период − возвраты`.
- `Осталось = Лимит − Потрачено` (может быть отрицательным — перерасход).
- `Прогноз = Потрачено + Σ плановых расходов этих категорий до конца периода`.
- `Свободно до конца периода` (FR-FIN-20) = баланс счетов «в бюджете» в базовой валюте − Σ плановых расходов + Σ плановых доходов до конца текущего периода.

### 6.7 Долги
- Выдача займа («мне должны»): баланс счёта уменьшается, остаток долга растёт. **Не расход.**
- Возврат займа мне: баланс растёт, остаток долга уменьшается. **Не доход.**
- Для «я должен» — зеркально.
- `Остаток долга = Σ выдач − Σ погашений` в валюте долга. Долг закрыт, когда остаток = 0.
- Прощение или списание: остаток превращается в расход (если мне должны) или доход (если я должен) явной операцией с категорией (FR-FIN-28).
- Сводка: «мне должны всего» и «я должен всего» в базовой валюте по последнему курсу.

### 6.8 Прогресс накоплений
- `Накоплено = Σ балансов привязанных счетов`, пересчитанная в валюту цели по последнему курсу (если валюта счёта отличается).
- `Прогресс = min(Накоплено / Целевая сумма, 100%)`.
- `Нужно в месяц = (Целевая − Накоплено) / число оставшихся месяцев` (если есть дата).

### 6.9 Межвалютные операции и округление
- Межвалютный перевод хранит **обе** суммы — списание и зачисление — каждую в своей валюте. Курс выводится из них и сохраняется для показа. Ничего не округляется задним числом.
- Конвертация для отчётов: `сумма_в_базовой = сумма × курс`. Результат округляется до минимальной единицы базовой валюты **по правилу «половина к чётному»** (банковское) [П]. Округление выполняется один раз на операцию, итоги суммируются из уже округлённых значений.
- Курс хранится как десятичное число с точностью не менее 10 значащих цифр (не `double`).

### 6.10 Дата и время
- Даты операций, задач и привычек хранятся как **локальная календарная дата** (без часового пояса). Время — опционально.
- Моменты технических событий (создание, изменение, журнал) хранятся в UTC.
- Напоминания задаются локальным временем + часовой пояс устройства и пересчитываются при смене пояса.

## 11. Допущения и открытые вопросы

**Допущения [П]** (принимаются, если вы не возразите при согласовании):
1. Дедлайн задачи — отдельное необязательное поле в v1 (R20).
2. Подзадачи — простые пункты без своих дат.
3. Плановые операции по умолчанию требуют подтверждения (не проводятся сами).
4. Смена валюты счёта с операциями запрещена.
5. База всегда зашифрована; PIN — опционален.
6. Папок заметок нет, используются теги.
7. Восстановление бэкапа — только полная замена.
8. Срок корзины — 30 дней, журнала — 12 месяцев, автокопий — 7.
9. Округление при конвертации — банковское (половина к чётному).
10. Эталонные устройства — iPhone 11 и Android среднего класса 2021 года.

**Открытые вопросы (не блокируют этап 3):**
1. Реальное Android-устройство для проверки голоса и уведомлений — где взять для периодических тестов (знакомые, недорогое б/у устройство)?
2. Нужен ли учёт «контрагентов» (кому платил) отдельной сущностью, а не текстом — по одному запросу из отзывов Qalta, оставлено вне v1.
3. Состав предустановленных категорий — согласуем на этапе 4 (UX).
