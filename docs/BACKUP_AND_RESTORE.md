## 1. Три разные операции

| | **Резервная копия (бэкап)** | **Экспорт данных** | **Перенос на новое устройство** |
|---|---|---|---|
| Зачем | Вернуть всё как было | Посмотреть или обработать данные в другой программе | Продолжить работу на другом телефоне |
| Что внутри | Вся база и настройки | Только выбранное: операции (CSV), заметки (Markdown) | То же, что в бэкапе |
| Можно ли восстановить приложение | Да, полностью | Нет; импортировать можно только операции из CSV, и это не восстановление | Да |
| Формат | `.uabk` | `.csv`, `.md` / `.zip` | `.uabk` (внешний бэкап + мастер SCR-90) |
| Где | Автокопии — в приложении; внешние — куда выбрал пользователь | Куда выбрал пользователь | Передаётся пользователем: Файлы, Telegram, компьютер, AirDrop |
| Шифрование | Автокопии — ключом устройства; внешние — паролем (по желанию) | Нет (открытый формат) | Паролем (рекомендуется) |

> **Простыми словами.** Автокопии на телефоне спасают от сбоя или ошибки («случайно удалил всё»), но не от потери телефона. Для этого нужна внешняя копия — файл, сохранённый в другом месте. Экспорт в CSV — не копия, а таблица для Excel.

## 2. Когда создаются копии (вопрос 1)

| Тип (`backup_metadata.kind`) | Когда | Где | Сколько хранится |
|---|---|---|---|
| `auto` | При уходе приложения в фон, если с прошлой автокопии прошло ≥ N часов (по умолчанию 24) **и** были изменения. Плюс фоновая задача ОС, без гарантии времени (ARCHITECTURE §12) | Папка приложения `backups/auto/` | Последние K (по умолчанию 7, настраивается 3–30) |
| `pre_risky` | Перед импортом CSV, массовым удалением (> 20 записей), очисткой корзины, сменой базовой валюты | `backups/auto/` | Входит в общий лимит K |
| `pre_migration` | Перед миграцией схемы | `backups/auto/` | Последние 2, отдельно от лимита K |
| `safety` | Перед восстановлением из файла | `backups/safety/` | Последняя 1 |
| `manual` | Пользователь нажал «Сохранить копию…» | Создаётся во временной папке и передаётся наружу. Внутри приложения не остаётся | — |

**Правило вытеснения:** самая старая копия удаляется только **после** того, как новая создана и проверена (FR-BAK-02, FR-BAK-14).

## 3. Как формируется файл (вопрос 2)

### 3.1 Автокопия (внутренняя)
1. `VACUUM INTO '<tmp>/snap.db'` — согласованный снимок открытой базы, без остановки приложения. Снимок зашифрован тем же ключом устройства [Гипотеза: поведение `VACUUM INTO` с sqlite3mc — проба этапа 7. Запасной вариант — Online Backup API SQLite].
2. Рядом пишется `manifest.json` (§3.3).
3. Оба файла упаковываются в `auto-2026-10-23T21-40.uabk.local` и перемещаются в `backups/auto/` атомарным переименованием.

Внутренние копии читаемы **только на этом устройстве** — они зашифрованы ключом из Keychain / Keystore.

### 3.2 Внешний файл `.uabk` (переносимый)
Контейнер — ZIP без сжатия базы (SQLite и так плотный, а шифрованное не сжимается):

```
U-Assistant-2026-10-23.uabk   (ZIP)
├── manifest.json        открытый: формат, версии, параметры шифрования
└── payload.bin          содержимое:
                         • без пароля — файл SQLite без шифрования (data.db) + summary.json, упакованные в ZIP
                         • с паролем — тот же ZIP, зашифрованный AES-256-GCM
```

**Шаги:**
1. Снимок базы с перешифровкой во **временную** папку приложения:
   - без пароля — расшифрованная копия (без ключа);
   - с паролем — тоже расшифрованная, затем шифруется паролем целиком.
   [Гипотеза: перешифровка снимка средствами sqlite3mc — `VACUUM INTO` с ключом в URI или `rekey` копии; проба этапа 7.]
2. `summary.json`: число записей по типам, период данных, имя приложения и устройство не указывается.
3. Упаковка `data.db` + `summary.json` → `inner.zip`.
4. С паролем: ключ = Argon2id(пароль, соль 16 байт; параметры §8), шифрование AES-256-GCM с nonce 12 байт → `payload.bin`. Без пароля: `payload.bin` = `inner.zip`.
5. `manifest.json` с SHA-256 от `payload.bin`.
6. Упаковка в итоговый `.uabk`. Временные файлы удаляются сразу после передачи и при следующем запуске (FR-SEC-06).

**Без пароля** в файле лежат данные в открытом виде. Перед первым экспортом без пароля пользователь видит: «Без пароля этот файл сможет открыть любой, к кому он попадёт. Установить пароль?»

### 3.3 `manifest.json`
```json
{
  "format": "uabk",
  "format_version": 1,
  "app": "U-Assistant",
  "app_version": "1.0.0+12",
  "schema_version": 1,
  "created_at": "2026-10-23T16:40:12Z",
  "payload_sha256": "9f2c…",
  "encrypted": true,
  "kdf": { "name": "argon2id", "memory_kib": 65536, "iterations": 3, "parallelism": 1, "salt_b64": "…" },
  "cipher": { "name": "aes-256-gcm", "nonce_b64": "…" }
}
```
Манифест открыт, чтобы до ввода пароля проверить формат и версию. Число записей и даты данных — внутри зашифрованного `summary.json`.

## 4. Как обеспечивается целостность (вопрос 3)
1. **SHA-256** всего `payload.bin` в манифесте. Проверяется до любой другой работы.
2. **Тег AES-GCM** (для зашифрованных) — любое изменение байта или неверный пароль дают ошибку расшифровки, а не мусорные данные.
3. **`PRAGMA integrity_check`** открытого снимка — при создании (до признания копии успешной) и при восстановлении (до подмены базы).
4. **Сверка счётчиков** из `summary.json` с фактическими строками снимка.

Копия, не прошедшая хотя бы одну проверку при создании, удаляется и не вытесняет старые (FR-BAK-14).

## 5. Версия формата (вопрос 4)
- `format_version` — версия контейнера (структура ZIP, манифест, шифрование). Меняется редко.
- `schema_version` — версия схемы базы внутри (drift `schemaVersion`).
- `app_version` — справочно, для диагностики.

---

## 6. Несовместимые версии (вопрос 5)

| Ситуация | Поведение |
|---|---|
| `format_version` > поддерживаемого | «Копия создана в более новой версии приложения. Обновите приложение» — отказ, данные не тронуты (AC-13) |
| `schema_version` > текущей | Так же — отказ |
| `schema_version` < текущей | Миграции drift прогоняются **на временной копии** до подмены. Ошибка миграции → отказ, текущие данные не тронуты |
| `format_version` < текущей | Поддерживаются все прошлые версии формата (код чтения старых форматов не удаляется) |
| Не `.uabk` или повреждён ZIP | «Это не файл копии U-Assistant» |

## 7. Место сохранения (вопрос 6)
- **iOS:** системное меню «Поделиться» (`UIActivityViewController`): «Сохранить в Файлы» (в том числе iCloud Drive, если он включён у пользователя), AirDrop, Telegram, почта.
- **Android:** системное «Поделиться» или «Сохранить как» через SAF (выбор папки, Google Диск, флешка). Разрешения на хранилище не нужны.
- Приложение не знает, куда именно сохранён файл. «Внешний бэкап выполнен» отмечается при успешном завершении системного диалога (`exported_at`).
- Платного облака нет. Если пользователь сам выбрал свой облачный диск — это его выбор (мастер-промпт §10).

## 8. Защита зашифрованных копий (вопрос 10)
- **Шифр:** AES-256-GCM (аутентифицированное шифрование: и тайна, и проверка целостности).
- **Ключ из пароля:** Argon2id. Стартовые параметры — 64 МиБ памяти, 3 итерации, 1 поток. Калибруются на слабом Android так, чтобы вывод ключа занимал 0,5–1,5 с [Гипотеза — проба этапа 7, TECH_RESEARCH §6]. Параметры пишутся в манифест, поэтому их можно менять, не ломая старые файлы.
- **Пакет:** `cryptography` (Apache-2.0) с ускорением `cryptography_flutter`. Вычисление — в отдельном isolate, чтобы интерфейс не зависал.
- **Пароль:**
  - не хранится и не запоминается, вводится при каждом экспорте и восстановлении (решение §9 USER_FLOWS);
  - минимум 8 символов;
  - индикатор сложности [П].
- **Потеря пароля = потеря копии.** Явное предупреждение и подтверждение при включении (DLG-09). Восстановить без пароля невозможно — это свойство шифрования, а не ограничение приложения.

## 9. Восстановление (вопрос 7)

```
Выбор файла ─▶ Проверка формата и версии ─▶ (Пароль ─▶ Расшифровка) ─▶ SHA-256 / GCM
     ─▶ Распаковка во временную папку ─▶ integrity_check ─▶ Миграции (если старше)
     ─▶ Сводка пользователю ─▶ DLG-07 (удержание) ─▶ Страховочная копия текущих данных
     ─▶ Закрыть базу ─▶ Зашифровать снимок ключом устройства ─▶ Атомарная подмена файла базы
     ─▶ Открыть базу ─▶ Пересоздать уведомления (reconcile) ─▶ Итог
```

**Атомарность:** новый файл базы готовится рядом (`u_assistant.db.new`), затем одно переименование заменяет старый. Если процесс прервётся до переименования — старая база цела. Если после — новая база полная. Страховочная копия позволяет вернуться к состоянию «до восстановления» (SCR-88 → автокопии → «safety»).

После восстановления:
- служебные таблицы `scheduled_notification` и `search_index` пересобираются;
- разрешения (уведомления, календарь) запрашиваются заново — они принадлежат устройству, а не данным.

## 10. Дубликаты (вопрос 8)
Восстановление в v1 — **только полная замена** (D-013), поэтому дубликатов не бывает по построению (AC-11). Слияние двух баз требует логики синхронизации — вне v1.

Импорт CSV — другая операция, у неё своя защита от повторов (FR-FIN-39, AC-21).

## 11. Повреждённые файлы (вопрос 9)

| Повреждение | Где обнаружится | Сообщение |
|---|---|---|
| Не ZIP или нет манифеста | Шаг 1 | «Это не файл копии U-Assistant» |
| Несовпадение SHA-256 | Шаг 2 | «Файл повреждён (возможно, не до конца скопирован). Текущие данные не изменены» (AC-12) |
| Ошибка GCM | Расшифровка | «Неверный пароль или файл повреждён» (AC-14). После 5 попыток — задержка |
| `integrity_check` ≠ ok | После распаковки | «Данные в копии повреждены. Текущие данные не изменены» |
| Повреждена текущая база при запуске | Открытие | SCR-03: восстановить из последней автокопии, из файла или начать с нуля |

## 12. Предупреждения пользователю (вопрос 11)

| Ситуация | Где и как |
|---|---|
| Внешнего бэкапа не было > 14 дней (настраивается) | Строка на «Сегодня» и в «Настройках»; раз в неделю — уведомление [П] |
| Автокопия не удалась 2 раза подряд или не делалась 3 дня при активном использовании | Строка-предупреждение с причиной (нет места, ошибка записи) — FR-BAK-13 |
| Нет места | «Не хватает места: нужно ~N МБ». Старые копии не удаляются |
| Экспорт без пароля | Однократное предупреждение (§3.2) |
| Восстановление заменит данные | DLG-07 с числом текущих записей |

**Проверка места:** требуется ≥ 2,2 × размер базы + 50 МБ свободно (снимок + архив + запас) [П].

## 13. Тестирование восстановления (вопрос 12)

| Тест | Уровень | Проверяет |
|---|---|---|
| Бэкап → восстановление → сравнение снимков всех таблиц (кроме служебных) | Интеграционный, база в памяти и на диске | AC-11: ничего не потеряно и не задвоено |
| Изменение одного байта payload | Unit | AC-12 |
| Манифест с `format_version` / `schema_version` + 1 | Unit | AC-13 |
| Неверный пароль | Unit | AC-14 |
| Восстановление копии схемы v1 в приложение со схемой vN | Интеграционный (на снимках из `drift_schemas`) | Миграции на временной копии |
| Прерывание на каждом шаге (симуляция исключения) | Интеграционный | Текущая база цела; временные файлы убраны |
| Нет места (фейк файловой системы) | Сценарий | Старые копии не удалены, сообщение верное |
| Ротация: K + 1 копий | Сценарий | Удаляется самая старая и только после проверки новой |
| Ручной перенос iPhone → Android-эмулятор и обратно | Ручной, перед вехой M3 | Переносимость между платформами |
| Время на базе 50 000 операций | Производительность | NFR-PERF-06 |

## 14. Экспорт отдельных данных
- **CSV операций:** колонки `date; time; type; amount; currency; amount_base; account; category; subcategory; note; tags; transfer_id`. Разделитель на выбор, UTF-8 с BOM, суммы с десятичным разделителем по выбору. Шапка всегда на английском [П] — так файл проще импортировать в другие программы. В интерфейсе подписи на русском.
- **Markdown заметок:** одна заметка — один `.md` (имя = заголовок, очищенный от недопустимых символов); несколько — `.zip`. Ссылки на записи превращаются в текст `[задача: Позвонить преподавателю]`.
- Экспорт явно подписан «не резервная копия» (FR-BAK-12).
