## 0. Как читать

### 0.1 Шаблон экрана (18 пунктов мастер-промпта)

| № | Пункт | Где в описании |
|---|---|---|
| 1 | Название | Заголовок раздела `SCR-xx` |
| 2 | Цель | **Цель** |
| 3 | Пользователь и задача | **Задача пользователя** |
| 4–5 | Структура сверху вниз и визуальные блоки | **Структура** (нумерованный список блоков с компонентами из DESIGN_SYSTEM §8) |
| 6 | Данные | **Данные** |
| 7–8 | Кнопки и что происходит при нажатии | **Действия** (таблица) |
| 9 | Фильтры и сортировки | **Фильтры** |
| 10 | Состояния | **Состояния** |
| 11 | Переходы | **Переходы** |
| 12 | Связь с базой | **База** — какие записи читаются и пишутся. Названия сущностей предварительные, точная схема — этап 6 (DATABASE.md) |
| 13 | Доступность | **Доступность** — только отличия от общих правил §0.2 |
| 14–15 | Светлая / тёмная тема | **Темы** — только отличия от §0.3 |
| 16–17 | iOS / Android | **Платформы** — только отличия от §0.4 |
| 18 | Критерии приёмки | **Приёмка** |

Если пункт совпадает с общими правилами раздела 0, он пишется как «— (общие правила)». Так спецификация не дублирует одно и то же 60 раз, но каждый пункт по каждому экрану покрыт.

### 0.2 Общие правила доступности (для всех экранов)
- Все интерактивные элементы — от 44×44 pt / 48×48 dp, расстояние между ними — от 8 pt.
- Порядок чтения диктором совпадает с визуальным: сверху вниз, слева направо.
- Иконки рядом с текстом скрыты от диктора. Иконки-кнопки имеют метку («Поиск», «Настройки», «Назад»).
- Чекбоксы, кольца и переключатели озвучивают состояние: «выполнено / не выполнено», «выбрано».
- Цвет никогда не единственный носитель смысла: просрочка — красный **и** слово «Просрочено»; категория — цвет **и** название.
- Системный размер шрифта до 200%: строки растут в высоту, текст переносится, суммы не обрезаются. Сводки в две колонки перестраиваются в одну при размере ≥ 150%.
- «Уменьшить движение» — анимации заменяются появлением.
- Каждый жест имеет кнопку-альтернативу (NFR-A11Y-06).
- Изменения после действия («Сохранено», «Удалено») озвучиваются вежливо, без перехода фокуса.

### 0.3 Общие правила тем
- **Светлая:** фон `bg` (#FFFFFF), экраны-формы — `bgGrouped` (#F2F2F7) с группами `surfaceGrouped`.
- **Тёмная:** фон #000000, группы и листы #1C1C1E, цвета категорий — тёмные значения DESIGN_SYSTEM §2.2, акцент #4A8BF5. Тени не используются.
- Цветные пиктограммы категорий и кольца используют токен темы. Белая пиктограмма на цветном квадрате одинакова в обеих темах.

### 0.4 Общие правила платформ
| | iOS | Android |
|---|---|---|
| Заголовок экрана первого уровня | Крупный, сворачивается при прокрутке | Top App Bar (medium), сворачивается в small |
| «Назад» | «‹ Экран» + свайп от левого края | Системный «Назад» + стрелка в панели |
| Листы | Системный лист со свайпом вниз | Modal bottom sheet, системный «Назад» закрывает |
| Диалоги | Alert / action sheet | Material dialog / меню |
| Переключатели | Segmented control | Segmented button |
| Нижняя панель | Tab bar с размытием | Navigation Bar M3 |
| Тактильная отдача | Taptic Engine | `HapticFeedback` |
| Сохранение стека вкладки | Да | Да; «Назад» в корне вкладки → «Сегодня», с «Сегодня» → выход |

### 0.5 Общие состояния
Каждый экран со списком или данными проектируется для состояний из USER_FLOWS §7:
- пусто впервые;
- пусто после фильтра;
- загрузка (заглушки после 300 мс);
- частичные данные (нет курса);
- нет разрешения;
- ошибка действия;
- ошибка экрана.

В описаниях экранов перечислено только то, что для этого экрана специфично.

### 0.6 Общая связь с базой
- Экраны не обращаются к базе напрямую. Они получают данные из **репозиториев** и подписаны на изменения: экран обновляется сам, когда данные изменились где-то ещё.
- Любое изменение из нескольких записей выполняется одной транзакцией (NFR-REL-01).
- Мягко удалённые записи (`deleted_at` не пусто) не показываются нигде, кроме корзины.

## 2. Вне оболочки

### SCR-01 Блокировка
- **Цель:** не дать постороннему увидеть данные при запуске и возврате в приложение.
- **Задача пользователя:** быстро войти — по лицу или отпечатку, иначе PIN.
- **Структура:**
  1. Название приложения (`title2`) по центру верхней трети.
  2. Подпись «Введите код» (`subhead`).
  3. 4–6 точек ввода PIN.
  4. Цифровая клавиатура 3×4: цифры, справа внизу «⌫», слева внизу кнопка биометрии (иконка лица или отпечатка).
  5. Текстовая кнопка «Забыли код?» внизу.
- **Данные:** длина PIN, включена ли биометрия, счётчик неудачных попыток и время блокировки (защищённое хранилище, не база).
- **Действия:**

| Элемент | Результат |
|---|---|
| Цифра | Точка заполняется. После последней цифры — проверка. Верно → последний экран (или запись из уведомления). Неверно → точки трясутся, тактильная «ошибка», «Неверный код. Осталось попыток: 3» |
| Биометрия | Системный запрос. Успех → вход. Отмена → остаётся PIN |
| «Забыли код?» | Лист с объяснением: сбросить код можно только удалив данные и восстановив их из бэкапа. Кнопки «Удалить данные и восстановить» (→ DLG-08) и «Отмена» |

- **Фильтры:** —
- **Состояния:**
  - обычное;
  - системный запрос биометрии поверх при открытии;
  - задержка после 5 ошибок: «Попробуйте через 30 секунд», клавиатура неактивна, обратный отсчёт.
- **Переходы:** → последний экран / запись из уведомления / DLG-08.
- **База:** не читается до успешного входа. Ключ базы из Keychain/Keystore доступен независимо от PIN (D-014).
- **Доступность:** цифры озвучиваются; точки — «введено 3 цифры из 4». Ошибка озвучивается.
- **Темы:** — (общие правила).
- **Платформы:**
  - iOS — Face ID / Touch ID, строка `NSFaceIDUsageDescription`;
  - Android — BiometricPrompt, в Activity — `FlutterFragmentActivity` (TECH_RESEARCH §6).
- **Приёмка:**
  - AC-25;
  - после 5 неверных попыток ввод блокируется на 30 с, затем на 1, 5 и 15 минут;
  - содержимое не видно в переключателе приложений, пока экран заблокирован.

### SCR-02 Онбординг
- **Цель:** настроить минимум для работы и честно сказать про локальное хранение.
- **Задача пользователя:** начать пользоваться за 30 секунд.
- **Структура (3 шага, у каждого кнопка «Далее» внизу и точки-индикаторы шага):**
  1. **«Основная валюта».** Список валют с поиском, KZT выбран и закреплён сверху. Подпись: «В ней считаются общие итоги. Можно изменить позже». Ссылка внизу — «Восстановить из бэкапа».
  2. **«Сколько у вас наличных?».** Поле суммы (клавиатура как в SH-02). Кнопки «Создать счёт» и «Пропустить».
  3. **«Данные хранятся только на этом телефоне».** Три строки с иконками: «Без регистрации», «Делайте резервную копию — файл можно сохранить куда угодно», «Если телефон потеряется, данные восстановятся только из копии». Кнопка «Начать».
- **Данные:** справочник валют ISO 4217 (встроен); создаются настройка базовой валюты, счёт «Наличные» и категории по умолчанию.
- **Действия:**

| Элемент | Результат |
|---|---|
| Валюта + «Далее» | Сохраняет базовую валюту, шаг 2 |
| «Восстановить из бэкапа» | → SCR-89 |
| «Создать счёт» | Счёт «Наличные» в базовой валюте с начальным балансом (может быть 0), шаг 3 |
| «Пропустить» | Шаг 3 без счёта |
| «Начать» | → SCR-10, с подсказкой «Нажмите «Добавить», чтобы записать первую трату или задачу» |

- **Фильтры:** поиск валюты по коду и названию.
- **Состояния:** приложение закрыто на шаге 2 или 3 → при следующем запуске онбординг продолжается с того же шага.
- **Переходы:** → SCR-10 / SCR-89.
- **База:** пишет `AppSettings.baseCurrency`, `Account`, набор `Category`. Всё на шагах 1–2 — одной транзакцией при «Далее».
- **Доступность:** — (общие правила).
- **Темы:** — (общие правила).
- **Платформы:** разрешения здесь не запрашиваются (P10).
- **Приёмка:** ≤ 3 экранов; от запуска до первой траты ≤ 30 с; без выбора валюты дальше пройти нельзя, остальное можно пропустить.

### SCR-03 Восстановление после сбоя (К)
Как SCR-89, но открывается сам, если база не открылась (F24). Заголовок «Не удалось открыть данные». Подпись: «Ваши резервные копии целы».

Три действия:
- «Восстановить из копии от {дата, время}» — основное;
- «Восстановить из файла» → выбор файла;
- «Начать с нуля» — диалог с удержанием кнопки; повреждённый файл сохраняется для диагностики.

**Приёмка:** приложение не падает в цикле и ничего не удаляет без явного выбора.

## 3. Сегодня

### SCR-10 Сегодня
> Эталон: прототип «D · Нативный → Сегодня».

- **Цель:** за 5 секунд показать, что важно сегодня — дела, привычки, деньги — и дать отметить выполненное.
- **Задача пользователя:** утром спланировать день, в течение дня отмечать сделанное, понять, сколько можно потратить.
- **Структура:**
  1. **Панель заголовка:** справа кнопки «Поиск» и «Настройки»; крупный заголовок «Сегодня» с иконкой-календарём текущего числа; под ним дата «Пятница, 23 октября».
  2. **Строка-уведомление** о рисках (не больше одной, по приоритету): нет внешнего бэкапа > 14 дней, автобэкап не удался, напоминания ненадёжны, нет курса.
  3. **Сводка денег** (DESIGN_SYSTEM §8.7): «Можно потратить» + сумма + «до {даты конца периода}»; «Потрачено» сегодня + мини-гистограмма за 7 дней.
  4. **Строка «Ждёт подтверждения»** — если есть плановые операции с наступившей датой: «Интернет ждёт подтверждения, 7 990 ₸ ›». Если их несколько — «3 платежа ждут подтверждения ›».
  5. **Раздел «Просрочено»** (заголовок `danger`): задачи с датой раньше сегодня. Больше 3 → три строки и «Ещё N».
  6. **Раздел «Дела»:** задачи на сегодня — сначала со временем по времени, затем без времени по приоритету. До 7 строк, затем «Ещё N».
  7. **Раздел «Привычки»:** кольца привычек на сегодня, горизонтальный ряд (прокрутка, если не помещаются).
  8. **Раздел событий календаря телефона** (если включено), заголовок по времени дня: «Утром / Днём / Вечером» — по первому событию [П]. Только просмотр.
  9. **Раздел «Платежи на неделю»** — плановые операции на 7 дней, до 3 строк.
  10. **Нижняя панель.**
- **Данные:** задачи (дата ≤ сегодня, статус «активна»), привычки на сегодня с отметками, события системного календаря на сегодня, плановые операции, показатель «Можно потратить» (§6.6), сумма расходов сегодня и по дням за 7 дней, статус бэкапа и надёжности напоминаний.
- **Действия:**

| Элемент | Результат |
|---|---|
| Чекбокс задачи | Выполнено: зачёркивание, через ~1 с строка уходит; «Выполнено · Отменить». У повторяющейся — следующий экземпляр (F08) |
| Строка задачи | → SCR-21 |
| Свайп строки влево / «⋯» | Перенести (Сегодня, Завтра, Выходные, Следующая неделя, Дата, Без даты) / Удалить |
| Кольцо привычки | Отметка; повторное нажатие снимает |
| Сводка денег | → SCR-30 |
| «Ждёт подтверждения» | → SCR-13 |
| Строка-уведомление | → соответствующий экран: SCR-88 / SCR-85 / SCR-44 |
| Событие календаря | Открывает событие в системном календаре |
| Платёж | → SCR-39 |
| «Поиск» / «Настройки» | → SCR-70 / SCR-80 |
| Иконка-календарь в заголовке | → SCR-11 (день) |

- **Фильтры:** нет. Какие разделы показывать — в настройках (SCR-83).
- **Состояния:**
  - **первый день** — подсказка про «Добавить» вместо пустых разделов;
  - **пустой день** — «На сегодня ничего не запланировано» и две текстовые кнопки «Добавить задачу» / «Записать расход»;
  - **нет счетов** — сводка заменяется строкой «Добавьте счёт, чтобы видеть деньги»;
  - **нет курса** — сумма «Можно потратить» с подписью «неполная: нет курса USD»;
  - **календарь без разрешения** — раздел скрыт.
- **Переходы:** см. «Действия».
- **База:** читает `Task`, `Habit` + `HabitCheck`, `RecurringRule` / плановые `Transaction`, `Account` (итог), `Budget` (период), `BackupMetadata`. Пишет: статус задачи, `HabitCheck`, `ActivityLog`.
- **Доступность:** сводка денег озвучивается одной фразой: «Можно потратить 184 500 тенге до 5 ноября. Сегодня потрачено 3 500 тенге». Мини-гистограмма — «Траты за 7 дней, сегодня меньше среднего».
- **Темы:** — (общие правила).
- **Платформы:** на Android заголовок «Сегодня» — в Top App Bar, иконка-календарь не показывается [П].
- **Приёмка:**
  - на iPhone SE без прокрутки видны заголовок, сводка денег и первая задача;
  - выполнение задачи отражается в списке ≤ 100 мс и отменяется;
  - тест «5 секунд» (USER_FLOWS §8, задание 5);
  - FR-HAB-03: привычка отмечается в 1 нажатие;
  - FR-FIN-20.

### SCR-11 Календарь
- **Цель:** увидеть план на день, неделю или месяц и перенести дела.
- **Задача пользователя:** понять загрузку и найти свободный день.
- **Структура:**
  1. Заголовок «‹ Сегодня», название месяца крупно, справа «Сегодня» (возврат к текущей дате) и «Фильтр».
  2. Переключатель «День / Неделя / Месяц».
  3. **Месяц:** сетка 7×6, у дня до 3 цветных точек (задачи цветом проекта, платежи — `accent`, события — цветом календаря), выбранный день — круг `accent`. Под сеткой — список выбранного дня.
  4. **Неделя:** 7 колонок-дней сверху (число и точки), под ними список выбранного дня.
  5. **День:** «Весь день» (задачи без времени, привычки), затем список по часам (только часы с записями, без пустой сетки) [П].
  6. Кнопка «Добавить» в нижней панели создаёт задачу на выбранную дату.
- **Данные:** задачи с датами (включая вычисленные будущие экземпляры повторов), привычки, плановые операции, сроки долгов, дедлайны проектов и целей, события системного календаря.
- **Действия:**

| Элемент | Результат |
|---|---|
| День в сетке | Выбирает день, список ниже обновляется |
| Строка | → экран записи |
| «⋯» строки задачи → «Перенести» | Выбор даты (FR-CAL-04); перетаскивание в неделе — дополнительный способ |
| «Фильтр» | Лист с переключателями типов: задачи, привычки, платежи, долги, дедлайны, календарь телефона |
| «Сегодня» | Прокрутка к текущей дате |
| Свайп по сетке влево / вправо | Следующий / предыдущий месяц; дублируется стрелками у названия месяца |

- **Фильтры:** типы записей (сохраняются локально).
- **Состояния:** пустой день — «Свободный день» и «Добавить задачу». Календарь телефона без разрешения — пункт в фильтре «Разрешить доступ».
- **Переходы:** → SCR-21, SCR-27, SCR-39, SCR-41, SCR-23, SCR-25, системный календарь.
- **База:** только чтение, плюс перенос задачи (`Task.date`). Системные события не пишутся (FR-CAL-05).
- **Доступность:** день в сетке озвучивается «23 октября, 3 задачи, 1 платёж». Точки не озвучиваются отдельно.
- **Темы:** — (общие правила).
- **Платформы:** на Android выбор даты в «Перенести» — Material Date Picker; на iOS — встроенный календарь (inline) в листе.
- **Приёмка:** AC-22 (системные события без дублей); повторяющаяся задача видна во всех будущих днях, но в базе только один экземпляр; FR-CAL-01…07.

### SCR-12 Предстоящие (К → SCR-11)
Список без сетки: группы по дням на 7 / 14 / 30 дней (переключатель). Те же строки и действия, что в SCR-11. Пустое состояние — «Ближайшие 7 дней свободны». Открывается из «Сегодня» → «Ещё» в разделе платежей и из меню календаря.

### SCR-13 Ожидают подтверждения
- **Цель:** провести плановые операции, дата которых наступила, без лишних действий.
- **Задача пользователя:** подтвердить пришедший счёт за интернет, иногда с другой суммой.
- **Структура:**
  1. Заголовок «‹ Назад», «Ждут подтверждения».
  2. Список: иконка категории, название, счёт, плановая дата, сумма.
  3. Под каждой строкой две текстовые кнопки «Подтвердить» и «Ещё…».
  4. Внизу кнопка «Подтвердить все (N)», если строк больше одной.
- **Данные:** плановые операции со статусом «ожидает» и датой ≤ сегодня.
- **Действия:**

| Элемент | Результат |
|---|---|
| «Подтвердить» | Лист с суммой (можно изменить) и счётом → «Готово» → операция становится фактической; «Подтверждено · Отменить» |
| «Ещё…» | Меню: «Пропустить этот раз», «Перенести», «Открыть правило» |
| «Подтвердить все» | Все строки с плановыми суммами — одной транзакцией |

- **Фильтры:** —
- **Состояния:** пусто — экран не открывается: строка на «Сегодня» исчезает. Если открыт из старой ссылки — «Нечего подтверждать».
- **Переходы:** → SCR-39, назад.
- **База:** `Transaction` (плановая → фактическая), `RecurringRule` (следующая дата), `ActivityLog`.
- **Доступность:** — (общие правила). **Темы:** — (общие правила). **Платформы:** — (общие правила).
- **Приёмка:** подтверждение меняет баланс счёта ровно один раз; пропуск не меняет баланс и сдвигает правило; FR-FIN-18.

### SCR-14 Активность (К)
Лента журнала действий по дням: иконка типа, «Выполнена задача «…»», время. Переключатель «Неделя / Месяц», фильтр типа. Сверху сводка (C): «Выполнено 23 задачи, отмечено 15 привычек, потрачено 64 200 ₸». Нажатие на запись открывает её, если она не удалена окончательно. Пустое состояние — «Здесь появятся ваши действия». База — `ActivityLog` (только чтение). FR-HIS-01, FR-HIS-05.

## 4. Дела

### SCR-20 Задачи
- **Цель:** управлять всеми задачами в нужном разрезе.
- **Задача пользователя:** разобрать входящие, посмотреть, что впереди, найти задачу.
- **Структура:**
  1. Заголовок вкладки «Дела»; переключатель «Задачи / Проекты / Цели / Привычки» под заголовком.
  2. Ряд списков (чипы): Входящие (N) · Сегодня · Предстоящие · Все · Выполненные.
  3. Список задач (DESIGN_SYSTEM §8.4): группировка «по дате» (Просрочено, Сегодня, Завтра, Эта неделя, Позже, Без даты) или «по проекту».
  4. Справа в заголовке «⋯»: Сортировка, Группировка, Выбрать, Повторяющиеся задачи, Корзина.
- **Данные:** задачи с проектом (цвет), тегами, датой, дедлайном, приоритетом, количеством подзадач, флагами «повтор», «напоминание», «есть заметка».
- **Действия:**

| Элемент | Результат |
|---|---|
| Чип списка | Меняет список; выбор запоминается |
| Чекбокс / строка / свайп | Как в SCR-10 |
| «Добавить» (на этой вкладке) | SH-04 с предзаполнением по текущему списку: «Сегодня» → дата сегодня |
| «⋯ → Выбрать» | Режим выбора: внизу панель «Перенести, Проект, Удалить» (FR-GEN-10) |
| «⋯ → Повторяющиеся» | → SCR-28 |

- **Фильтры:** панель «Фильтр» (кнопка справа от чипов) — статус, приоритет, проект, тег, есть дата, есть дедлайн. Сортировка: по дате, приоритету, созданию, вручную (только в «Входящих» и проекте).
- **Состояния:**
  - «Входящие» пусты — «Здесь задачи без даты и проекта. Всё разобрано»;
  - «Выполненные» — с группировкой по дате выполнения, хранятся по сроку журнала.
- **Переходы:** → SCR-21, SCR-28, SCR-73.
- **База:** `Task`, `Project`, `Tag` (чтение); статус, дата, проект (запись).
- **Доступность:** счётчик у «Входящие» озвучивается («Входящие, 4 задачи»).
- **Темы:** — (общие правила).
- **Платформы:** на Android чипы — Filter chips M3.
- **Приёмка:** FR-TSK-03; режим выбора меняет N задач одной операцией и отменяется одной кнопкой; ручная сортировка доступна кнопками «Выше / Ниже», а не только перетаскиванием.

### SCR-21 Задача
- **Цель:** посмотреть и изменить всё о задаче.
- **Задача пользователя:** уточнить срок, добавить подзадачи, связать с проектом.
- **Структура (экран-форма на `bgGrouped`):**
  1. Навигация «‹ Дела», справа «⋯».
  2. Строка: большой чекбокс + название (редактируется на месте, `title3`).
  3. **Группа «Когда»:** Дата (и время), Дедлайн, Напоминания (список + «Добавить»), Повтор.
  4. **Группа «Где»:** Проект, Цель, Теги, Приоритет.
  5. **Подзадачи:** список с чекбоксами, «+ Подзадача», порядок кнопками «Выше / Ниже» в режиме правки.
  6. **Описание** (Markdown-подмножество, как в заметке).
  7. **Связанное:** заметки, операции → «+ Связать» (SCR-74).
  8. **История** (свёрнута): изменения «поле — было — стало».
- **Данные:** все поля задачи, подзадачи, напоминания, правило повтора, связи, история.
- **Действия:**

| Элемент | Результат |
|---|---|
| Любое поле | Изменение сохраняется сразу; напоминания пересчитываются (FR-REM-02) |
| «Повтор» | Лист: Нет / Ежедневно / По будням / Еженедельно (дни) / Ежемесячно / Свой интервал; режим «по расписанию / от выполнения»; окончание (никогда / до даты / N раз) |
| Изменение даты повторяющейся задачи по расписанию | DLG-02 «Только эта / Изменить расписание» |
| «⋯» | Пропустить этот раз (для повтора), Дублировать, Создать заметку, Удалить |
| «Удалить» | В корзину + «Отменить»; напоминания сняты (AC-07) |

- **Фильтры:** —
- **Состояния:**
  - задача выполнена — плашка сверху «Выполнена 22 октября, Вернуть»;
  - задача в корзине — открывается только из корзины, только для чтения, кнопка «Восстановить».
- **Переходы:** → SCR-23, SCR-25, SCR-72, SCR-52, SCR-32, SCR-74.
- **База:** `Task`, `Subtask`, `Reminder`, `RecurringRule`, `EntityTag`, связи, `ActivityLog`, история изменений.
- **Доступность:** поля формы — строки с меткой и значением («Дата, завтра, 9:00, кнопка»).
- **Темы:** — (общие правила).
- **Платформы:**
  - iOS — выбор даты и времени встроенным календарём в листе;
  - Android — Material Date Picker и Time Picker.
- **Приёмка:** AC-07, AC-08, AC-09, AC-10; FR-TSK-01…08; изменение даты переставляет уведомление ОС.

### SCR-22 Проекты (К → SCR-20)
Список проектов: цветной кружок, название, полоса прогресса (`fill` + цвет проекта), «12 из 20», срок справа (красный при просрочке). Группы: Активные, Приостановленные. Завершённые и архив — в фильтре. Добавить → лист «Новый проект» (название, цвет, цель, срок). Пусто — «Проект — это результат из нескольких задач. Например, «Подготовить диплом»».

### SCR-23 Проект
- **Цель:** вести крупный результат: задачи, сроки, заметки, прогресс.
- **Задача пользователя:** понять, сколько осталось, и добавить задачи.
- **Структура:**
  1. «‹ Проекты», «⋯».
  2. Цветной кружок и название (`largeTitle`), под ним цель (ссылка) и срок.
  3. Прогресс: «12 из 20 задач», полоса, прогноз «при текущем темпе — к 14 ноября» [П].
  4. Задачи: активные, затем «Выполненные (12)» свёрнуто.
  5. Заметки проекта.
  6. История (свёрнута).
- **Данные:** проект, его задачи, связанные заметки, история.
- **Действия:**

| Элемент | Результат |
|---|---|
| «Добавить» | SH-04 с проектом |
| «⋯» | Изменить, Приостановить, Завершить (DLG-03 при открытых задачах), В архив, Удалить |
| Цель | → SCR-25 |

- **Фильтры:** показывать выполненные (переключатель).
- **Состояния:** нет задач — «Добавьте первую задачу проекта»; завершён — плашка «Завершён 20 октября, Вернуть в работу».
- **Переходы:** → SCR-21, SCR-25, SCR-52.
- **База:** `Project`, `Task`, связи, `ActivityLog`.
- **Доступность / Темы / Платформы:** — (общие правила).
- **Приёмка:** FR-PRJ-01…03; прогресс не учитывает отменённые задачи.

### SCR-24 Цели (К → SCR-22)
Список целей: иконка типа (количественная / накопительная / результатная), название, прогресс в %, целевая дата. Фильтр по статусу. Пусто — «Цель — то, к чему вы идёте. Её прогресс собирается из задач, проектов или накоплений».

### SCR-25 Цель
- **Цель:** видеть прогресс к результату и всё, что к нему ведёт.
- **Задача пользователя:** понять, успеваю ли, и что делать дальше.
- **Структура:**
  1. «‹ Цели», «⋯».
  2. Название (`largeTitle`), критерий «как пойму, что достиг» (`subhead`).
  3. **Крупный прогресс** (выразительная деталь): «120 000 из 500 000 ₸» `amountL`, полоса и «24%».
  4. **Прогноз** (для накопительной и количественной с датой): «Нужно около 95 000 ₸ в месяц до 1 марта» / «В текущем темпе — к 12 мая».
  5. **Связанное** по группам: Счета (для накопительной), Проекты, Задачи, Привычки, Заметки.
  6. Для количественной — кнопка «Обновить значение» и история отметок.
- **Данные:** цель, привязанные счета и их балансы (через курс), связанные проекты и задачи, привычки, отметки значения.
- **Действия:**

| Элемент | Результат |
|---|---|
| «Обновить значение» | Лист с числом → новая отметка |
| При 100% | Строка «Цель достигнута? Отметить» (FR-GOL-04) |
| «⋯» | Изменить, Отметить достигнутой, Отменить, В архив, Удалить |
| Связанная запись | → её экран |

- **Фильтры:** —
- **Состояния:** нет курса для валюты счёта — прогресс «неполный» с переходом к SCR-44; достигнута — плашка с датой.
- **Переходы:** → SCR-35, SCR-23, SCR-21, SCR-27, SCR-52.
- **База:** `Goal`, `GoalProgressEntry` [П], связи, `Account`, `ExchangeRate`.
- **Доступность:** прогресс озвучивается полностью: «Накоплено 120 000 из 500 000 тенге, 24 процента».
- **Темы / Платформы:** — (общие правила).
- **Приёмка:** FR-GOL-01…04; §6.8 (расчёт накоплений).

### SCR-26 Привычки (К)
Список: кольцо сегодняшнего дня, название, «6 дней подряд», расписание. Нажатие на кольцо — отметка, на строку — SCR-27. Пусто — пример «Читать 20 минут» и «Создать привычку».

### SCR-27 Привычка
- **Цель:** видеть регулярность и управлять расписанием.
- **Задача пользователя:** отметить пропущенный вчера день, посмотреть серию.
- **Структура:**
  1. «‹ Привычки», название (`largeTitle`), цвет.
  2. Три числа в ряд: текущая серия, лучшая серия, процент за 30 дней.
  3. Календарь-сетка последних 5 недель: заполненный круг — выполнено, кольцо — частично, пусто — нет, штриховка — пауза.
  4. Группа настроек: расписание, напоминание, цель, пауза.
- **Данные:** привычка, отметки, расписание.
- **Действия:**

| Элемент | Результат |
|---|---|
| День в сетке | Переключить отметку (прошлые дни — да, будущие — нет) |
| «Пауза» | Лист: до даты / бессрочно; серия не ломается (FR-HAB-04) |

- **Фильтры:** —
- **Состояния:** на паузе — плашка «На паузе до 1 ноября, Возобновить».

- **База:** `Habit`, `HabitCheck`, `Reminder`.
- **Доступность:** день сетки озвучивается «20 октября, выполнено».
- **Темы / Платформы:** — (общие правила).
- **Приёмка:** FR-HAB-01…04; серия считается по расписанию (дни вне расписания её не ломают).

### SCR-28 Повторяющиеся задачи (К)
Служебный список серий: название, правило словами («каждый понедельник»), следующая дата, статус. Действия строки: Пауза / Возобновить / Завершить серию / Изменить правило. Пусто — «Повторяющихся задач нет». FR-TSK-06.

## 5. Быстрое добавление

### SH-01 Быстрое добавление
- **Цель:** записать что угодно из любого места за пару нажатий.
- **Задача пользователя:** выбрать, что записать.
- **Структура (лист):**
  1. Ручка листа, заголовок «Добавить», справа «Закрыть».
  2. Список из 6 строк (не плитки): иконка 30 pt в цвете типа + название — Расход, Доход, Перевод, Задача, Заметка, Голосом.
  3. Раздел «Шаблоны» — до 5 закреплённых операций строками: «Обед, 2 500 ₸».
- **Данные:** шаблоны, контекст вкладки (проект, счёт, категория).
- **Действия:**

| Элемент | Результат |
|---|---|
| Расход / Доход | → SH-02 |
| Перевод | → SH-03 |
| Задача | → SH-04 |
| Заметка | → SCR-52, новая |
| Голосом | → SCR-60 |
| Шаблон | Сразу создаёт операцию с сегодняшней датой; «Обед 2 500 ₸ сохранён · Отменить» |
| Долгое нажатие на «Добавить» в нижней панели | Сразу раздел шаблонов (ускоритель; тот же раздел есть в листе) |

- **Фильтры:** —
- **Состояния:** шаблонов нет — раздел скрыт.
- **Переходы:** см. «Действия».
- **База:** читает `Template`; шаблон пишет `Transaction`.
- **Доступность / Темы:** — (общие правила).
- **Платформы:** iOS — лист средней высоты (medium detent); Android — modal bottom sheet.
- **Приёмка:** FR-GEN-02; шаблон создаёт ровно одну операцию и отменяется.

### SH-02 Новый расход / доход
> Эталон: прототип «D · Нативный → Новый расход».

- **Цель:** записать трату или доход быстрее, чем открыть заметки.
- **Задача пользователя:** ввести сумму, при необходимости поменять категорию — и всё.
- **Структура (полноэкранный лист на `bgGrouped`):**
  1. «Отмена» — заголовок «Новый расход» — «Готово» (неактивна при сумме 0).
  2. Переключатель «Расход / Доход / Перевод». «Перевод» переключает на SH-03 без потери суммы.
  3. Сумма `amountXL` по центру; при калькуляции под ней «= 2 050 ₸».
  4. Ряд из 6 категорий: 5 последних для этого типа + «Все».
  5. Группа строк: Категория, Счёт (с балансом), Дата, Комментарий. Для дохода в «Подробнее» — переключатель «Это возврат» (FR-FIN-10).
  6. Ссылка «Подробнее»: теги, время, связь с задачей.
  7. Цифровая клавиатура с «000» и «⌫». Долгое нажатие на «⌫» стирает всё. Кнопка «±×÷» открывает ряд операций калькулятора.
- **Данные:** последние категории, счета с балансами, последний использованный счёт, контекст (категория или счёт, если открыт из них).
- **Действия:**

| Элемент | Результат |
|---|---|
| Цифры | Сумма с учётом дробных разрядов валюты счёта |
| Категория в ряду | Выбирает. Состояние «выбрано» — заливка цветом и подпись Semibold |
| «Все» | Лист категорий с поиском и строкой «+ Новая категория» (название, иконка, цвет, родитель) — создаёт и сразу выбирает |
| Счёт / Дата | Лист выбора; смена счёта на счёт в другой валюте меняет символ и разрядность |
| «Готово» | Сохраняет и закрывает; «Расход 3 500 ₸ сохранён · Отменить» |
| «Отмена» / свайп вниз | Без суммы — закрывает; с суммой — «Отменить ввод?» |

- **Фильтры:** поиск в листе категорий.
- **Состояния:**
  - **нет счетов** — строка «Счёт» заменяется на «Создать «Наличные»» одним нажатием;
  - **валюта без курса** — сохранить можно; под суммой подпись «Нет курса USD — в общих итогах не учтётся»;
  - **ошибка сохранения** — данные остаются в форме, вверху строка «Не удалось сохранить, повторить».
- **Переходы:** → SH-03, SCR-43 (через «Все» → «Изменить категории»).
- **База:** пишет `Transaction` (тип, сумма в минимальных единицах, валюта счёта, курс к базовой на дату — §6.4), `EntityTag`, связь с задачей; обновляет «последний счёт / категорию» в настройках.
- **Доступность:** сумма озвучивается «3 500 тенге»; клавиши — цифрами; выбранная категория — «Продукты, выбрано».
- **Темы:** клавиатура — `#D1D3D9` / `#2B2B2D`, клавиши — белые / `#5A5A5E`.
- **Платформы:** клавиатура своя на обеих платформах (одинаковая), системная скрыта. На iOS «Готово» сверху справа; на Android — дополнительно круглая кнопка подтверждения на клавиатуре [П].
- **Приёмка:** S1 ≤ 3 нажатий + ввод; FR-FIN-05, 06, 10, 12 (новая категория из формы); сумма никогда не хранится как дробное число.

### SH-03 Новый перевод
- **Цель:** переместить деньги между своими счетами, не искажая доходы и расходы.
- **Задача пользователя:** снял наличные с карты — записать.
- **Структура:** как SH-02, но вместо ряда категорий две строки:
  - «Откуда» и «Куда» (счёт с балансом) с кнопкой «⇅» между ними;
  - при разных валютах — вторая сумма «Зачислено» и строка «Курс: 1 USD = 470,50 ₸»;
  - в «Подробнее» — «Комиссия».
- **Данные:** счета, последний курс.
- **Действия:**

| Элемент | Результат |
|---|---|
| «⇅» | Меняет счета местами |
| Изменение «Зачислено» | Курс пересчитывается из двух сумм |
| Счёт «только отслеживать» в любой стороне | Появляется обязательная строка «Категория» с подписью «Такой перевод учитывается как расход» (или «как доход») |
| «Готово» | Пара связанных записей (+ расход-комиссия) одной транзакцией |

- **Фильтры:** —
- **Состояния:** одинаковые счета — «Готово» неактивна, подпись «Выберите разные счета».
- **Переходы:** → SH-02 (переключатель).
- **База:** две `Transaction` с общим `transferId`, опционально третья — комиссия.
- **Доступность / Темы / Платформы:** как SH-02.
- **Приёмка:** AC-01, AC-02, AC-03; FR-FIN-07, 08.

### SH-04 Новая задача
- **Цель:** записать задачу быстро, со сроком и напоминанием, если нужно.
- **Задача пользователя:** «завтра отправить отчёт, напомнить».
- **Структура (лист над клавиатурой):**
  1. «Отмена» — «Новая задача» — «Готово».
  2. Поле названия с пустым кругом-чекбоксом слева, фокус сразу.
  3. Ряд чипов: Сегодня / Завтра / Дата; Напомнить; Проект; Приоритет.
  4. Строка-итог `footnote`: «Срок: сб, 24 окт, напоминание в 09:00».
  5. «Подробнее» → полный экран SCR-21 с введёнными данными.
- **Данные:** проекты, время напоминания по умолчанию, контекст (проект, дата).
- **Действия:**

| Элемент | Результат |
|---|---|
| «Сегодня» / «Завтра» | Ставит дату, повторное нажатие снимает |
| «Дата» | Календарь + время |
| «Напомнить» | Ставит напоминание на время задачи или на время по умолчанию; повторное нажатие — выбор («В момент задачи», «За 15 мин», «За час», «Своё время», «Убрать») |
| «Готово» / «Готово» на клавиатуре | Сохраняет. При первом напоминании — сначала объяснение и разрешение на уведомления (F06) |

- **Фильтры:** —
- **Состояния:** без названия «Готово» неактивна; в названии распознана дата («завтра в 9») — она подсвечивается, предлагается «Поставить срок сб, 9:00?» с кнопкой ✕ [П, как у Todoist].
- **Переходы:** → SCR-21 («Подробнее»).
- **База:** `Task`, `Reminder`.
- **Доступность / Темы:** — (общие правила).
- **Платформы:** Android 12+ при первом напоминании — дополнительное объяснение про точные будильники (F06).
- **Приёмка:** S4 ≤ 5 нажатий + ввод; отказ в разрешении не мешает сохранить задачу, причина видна.

## 6. Деньги

### SCR-30 Деньги: обзор
- **Цель:** ответить «сколько у меня денег и всё ли в порядке» и дать доступ ко всем финансовым разделам.
- **Задача пользователя:** посмотреть баланс, бюджеты, ближайшие платежи.
- **Структура:**
  1. Заголовок «Деньги», справа «⋯» (Счета, Бюджеты, Регулярные платежи, Долги, Категории, Курсы, Шаблоны, Импорт, Экспорт, Корзина).
  2. Переключатель «Обзор / Операции / Расходы».
  3. **Общий баланс** — выразительная деталь: `amountL`, под ним «по курсу USD 470,50 от 20 октября».
  4. Две колонки между разделителями (как сводка «Сегодня»): «Можно потратить до 5 ноября» и «Расходы в октябре».
  5. Строка «Ждут подтверждения» (если есть).
  6. **Раздел «Счета»:** строки — иконка типа счёта цвета счёта, название, баланс; скрытые не показываются; итог по группам не нужен.
  7. **Раздел «Бюджеты»:** закреплённые бюджеты — строка с названием, «64 300 из 100 000 ₸» и полосой; перерасход — красный текст «превышен на 2 500 ₸».
  8. **Раздел «Платежи на неделю».**
  9. **Раздел «Долги»** — две строки «Мне должны» и «Я должен» с суммами (скрыт, если долгов нет).
  10. **Раздел «Накопления»** — накопительные цели с полосой (скрыт, если нет).
  11. **Раздел «Последние операции»** — 5 строк и «Все операции».
- **Данные:** счета с балансами, курсы, бюджеты с расходом, плановые операции, долги, накопительные цели, последние операции.
- **Действия:**

| Элемент | Результат |
|---|---|
| Общий баланс | Лист «Как посчитано»: счета в своих валютах, курсы, даты курсов |
| Строка счёта / бюджета / долга / цели / операции | → SCR-35 / 37 / 41 / 25 / 32 |
| «Все» у раздела | → полный список |
| «Добавить» | SH-02 |

- **Фильтры:** —
- **Состояния:**
  - **нет счетов** — экран сводится к пустому состоянию «Создайте первый счёт, например «Наличные»» и кнопке;
  - **нет курса** — у общего баланса подпись «неполный: нет курса USD», нажатие → SCR-44;
  - **разделы без данных** скрыты, кроме «Счета».
- **Переходы:** см. «Действия» и «⋯».
- **База:** `Account`, `Transaction` (агрегаты), `ExchangeRate`, `Budget`, `RecurringRule`, `Debt`, `Goal`. Только чтение.
- **Доступность:** общий баланс озвучивается вместе с пометкой «неполный» и её причиной.
- **Темы / Платформы:** — (общие правила).
- **Приёмка:** §6.3 (общий баланс), AC-16, FR-FIN-20; разделы долгов и накоплений не показываются пустыми.

### SCR-31 Операции
- **Цель:** найти и проверить любые операции.
- **Задача пользователя:** «куда ушли деньги вчера», «найти 3 500».
- **Структура:**
  1. Переключатель «Обзор / Операции / Расходы» (если открыт из вкладки) или «‹ Назад» и заголовок фильтра (если открыт из аналитики).
  2. Строка поиска (всегда видна).
  3. Чипы активных фильтров с «✕» и кнопка «Фильтр».
  4. Итог по выборке: «23 операции, −42 500 ₸» (доходы и расходы раздельно, если есть оба).
  5. Список по дням: заголовок дня (`footnote`) с суммой дня справа; строки операций (§8.4). Перевод — серая иконка «⇄», «Карта → Наличные», сумма серым без знака.
- **Данные:** операции с категорией, счётом, тегами; итоги по выборке.
- **Действия:**

| Элемент | Результат |
|---|---|
| Строка | → SCR-32 |
| Свайп влево / «⋯» | Дублировать, Удалить |
| «Фильтр» | Лист: период (пресеты + свой), тип, счёт, категория (дерево с подкатегориями), тег, сумма от–до. «Показать N операций» |
| «⋯ → Выбрать» | Массовые действия: Категория, Счёт, Дата, Удалить |

- **Фильтры:** см. выше; сортировка — по дате (по умолчанию) или по сумме.
- **Состояния:**
  - пусто после фильтра — «Нет операций по этим фильтрам», «Сбросить фильтры»;
  - пусто впервые — «Здесь будут операции. Запишите первый расход»;
  - длинный список — подгрузка по мере прокрутки.
- **Переходы:** → SCR-32.
- **База:** `Transaction` (чтение с фильтрами, индекс по дате, счёту, категории); удаление — мягкое (пара для перевода).
- **Доступность:** строка озвучивается «Такси, наличные, минус 1 500 тенге, 23 октября».
- **Темы / Платформы:** — (общие правила).
- **Приёмка:**
  - FR-FIN-11;
  - NFR-PERF-03 (10 000 операций без рывков);
  - сумма списка из аналитики совпадает с сегментом (AC-20);
  - поиск «3500» находит «3 500,00» (F12).

### SCR-32 Операция
- **Цель:** посмотреть и исправить операцию.
- **Структура (форма на `bgGrouped`):**
  1. «‹ Назад», «⋯».
  2. Иконка категории 44, сумма `amountL` (`positive` для дохода), под ней категория и дата.
  3. **Группа:** Категория, Счёт, Дата и время, Комментарий, Теги.
  4. **Группа «Связи»:** задача, долг, правило регулярного платежа, заметки.
  5. **Для перевода:** обе стороны (Откуда / Куда / Списано / Зачислено / Курс).
  6. История изменений (свёрнута).
- **Данные:** операция, связанные записи, история.
- **Действия:**

| Элемент | Результат |
|---|---|
| Поле | Правка сохраняется сразу. Для перевода меняются обе записи (FR-FIN-08) |
| «⋯» | Дублировать, Сделать шаблоном, Удалить |
| Связь | → запись |

- **Состояния:** операция из правила — подпись «Создана из «Интернет», ежемесячно».
- **База:** `Transaction`, история изменений, связи.
- **Задача пользователя / Фильтры / Доступность / Темы / Платформы:** — (общие правила).
- **Приёмка:** FR-FIN-05, 08, FR-HIS-02.

### SCR-33 Деньги: расходы (аналитика)
> Эталон: прототип «D · Нативный → Расходы».

- **Цель:** понять, куда уходят деньги, и дойти до конкретных операций.
- **Задача пользователя:** «почему в этом месяце больше», «сколько на транспорт».
- **Структура:**
  1. Переключатель вкладки «Обзор / Операции / Расходы».
  2. Переключатель периода «Неделя / Месяц / Полгода / Год»; стрелки ‹ › у даты для перехода между периодами.
  3. Итог: подпись «Всего», `amountL`, диапазон дат.
  4. **Столбики** (DESIGN_SYSTEM §9): по дням (неделя, месяц) или по месяцам (полгода, год), линия среднего.
  5. Подпись сравнения: «В сентябре было 210 800 ₸, сейчас на 12% больше».
  6. **Раздел «По категориям»:** кольцо (≤ 6 долей) и справа выбранная доля (название цветом, сумма, %, «Показать операции»).
  7. Список категорий: иконка, название, сумма, %, шеврон. Нажатие на подкатегорию раскрывает вложенные строки.
  8. **Раздел «Бюджеты»** — план и факт по каждому бюджету периода (полосы).
  9. Переключатель «Расходы / Доходы» в заголовке экрана (через «⋯» или отдельной кнопкой) [П].
- **Данные:** расходы по дням или месяцам за период, по категориям и подкатегориям, сравнение с прошлым периодом, бюджеты — всё в базовой валюте по курсам из операций (§6.4).
- **Действия:**

| Элемент | Результат |
|---|---|
| Столбец | Шапка показывает этот день; повторное нажатие возвращает итог. Долгое нажатие → операции этого дня |
| Доля кольца или строка категории | Выбирает категорию |
| «Показать операции» / шеврон | → SCR-31 с фильтром «период + категория (с подкатегориями)» |
| Строка бюджета | → SCR-37 |

- **Фильтры:** период, тип (расходы / доходы), счёт (в «⋯»).
- **Состояния:**
  - **нет данных за период** — «Пока нет расходов за октябрь» и «Записать расход», без пустых осей;
  - **нет курса** — пометка «неполные данные: нет курса USD» над итогом;
  - **больше 6 категорий** — шестая доля «Другое» объединяет остальные, в списке они видны полностью.
- **Переходы:** → SCR-31, SCR-37.
- **База:** агрегатные запросы к `Transaction` по периоду, категории, дню; `Budget`. Только чтение.
- **Доступность:**
  - график озвучивается сводкой «Траты по дням октября, максимум 1 октября — 62 000 тенге, в среднем 10 270»;
  - каждый столбец — отдельный элемент с подписью;
  - кольцо дублируется списком.
- **Темы:** цвета столбиков и долей — по теме (DESIGN_SYSTEM §2.2, §9).
- **Платформы:** — (общие правила).
- **Приёмка:**
  - AC-20 (сумма списка равна значению доли);
  - FR-FIN-29…35;
  - NFR-PERF-04 (≤ 500 мс на 50 000 операций);
  - переводы не входят в расходы (AC-01), а переводы на счёт «только отслеживать» — входят (AC-03).

### SCR-34 Счета / SCR-35 Счёт
**SCR-34 Счета:**
- **Структура:** итог в базовой валюте; группы по типу (Наличные, Карты, Счета и вклады, Кредиты); строки — иконка цвета счёта, название, баланс в своей валюте (и в базовой серым, если валюта другая); внизу «Скрытые и архивные (N)».
- **Действия:** строка → SCR-35; «Добавить» → лист «Новый счёт» (название, тип, валюта, начальный баланс, «в бюджете / только отслеживать», цвет); «⋯ → Порядок» — режим с кнопками «Выше / Ниже».

**SCR-35 Счёт:**
- **Структура:**
  1. Название, тип, баланс `amountL`.
  2. Кнопки-строки «Перевести», «Изменить баланс».
  3. Операции счёта по дням (как SCR-31).
  4. Группа настроек: валюта (только чтение при наличии операций, FR-FIN-03), учёт в бюджете, скрыть из общего баланса, цвет, архив.
- **Действия:**
  - «Изменить баланс» → поле фактического остатка → операция-корректировка на разницу (FR-FIN-02);
  - «Перевести» → SH-03 с этим счётом;
  - «⋯ → Удалить» → DLG-04.
- **Состояния:** архивный счёт — плашка «В архиве, Вернуть»; кредит — баланс со знаком минус и подписью «долг по кредиту».
- **База:** `Account`, `Transaction`.
- **Задача пользователя / Фильтры / Доступность / Темы / Платформы:** — (общие правила).
- **Приёмка:** §6.2 (баланс); FR-FIN-01…04; корректировка не попадает в доходы и расходы.

### SCR-36 Бюджеты / SCR-37 Бюджет
**SCR-36:**
- **Структура:** период сверху (‹ октябрь ›); строки бюджетов с полосой и «осталось N ₸»; закреплённые отмечены значком.
- **Действия:** «Добавить» → «Новый бюджет»: категории (мультивыбор), лимит, период (месяц от дня из настроек, неделя, год, свой), повторять, закрепить на обзоре, уведомлять на 80% / 100%.

**SCR-37:**
- **Структура:**
  1. Название, крупно «Осталось 35 700 ₸» (или «Превышен на 2 500 ₸» красным).
  2. Полоса и строка «64 300 из 100 000 ₸».
  3. Три числа: дневной темп «≈2 750 ₸ в день», дней осталось, прогноз с учётом плановых.
  4. Мини-столбики по дням периода.
  5. Операции бюджета.
- **Действия:** «⋯» — Изменить, Закрепить / Открепить, Удалить.
- **Состояния:** бюджет за прошлый период — только чтение.
- **База:** `Budget`, `BudgetCategory`, агрегаты `Transaction`.
- **Задача пользователя / Фильтры / Доступность / Темы / Платформы:** — (общие правила).
- **Приёмка:** §6.6; AC-18; FR-FIN-21…23; категория в двух бюджетах — предупреждение при создании (F13).

### SCR-38 Регулярные платежи / SCR-39 Правило (К)
- **SCR-38:** строки «Интернет, ежемесячно 26 числа, 7 990 ₸, следующий пн 26 окт». Сверху итог «≈ 48 300 ₸ в месяц».
- **SCR-39:**
  - **структура:** шаблон операции (как SH-02 без клавиатуры), правило повтора, дата начала и окончания, напоминание за N дней, «Проводить автоматически» (выкл. по умолчанию), история проведённых и пропущенных;
  - **действия:** «Пропустить следующий», «Остановить», «Удалить» (с вопросом про будущие плановые);
  - **база:** `RecurringRule`, плановые `Transaction`.
- **Приёмка:** FR-FIN-17…19; остановка правила удаляет будущие плановые записи, но не фактические.

### SCR-40 Долги / SCR-41 Долг
**SCR-40:**
- **Структура:** две секции «Мне должны» и «Я должен» с итогами в базовой валюте. Строки: контрагент, остаток, срок (красный при просрочке). Закрытые — в фильтре.
- **Действия:** «Добавить» → «Новый долг»: направление, кто, сумма, валюта, счёт, дата, срок, напоминание.

**SCR-41:**
- **Структура:**
  1. Контрагент, направление, остаток `amountL`.
  2. Полоса «погашено 5 000 из 15 000 ₸», срок.
  3. Кнопки-строки «Добавить погашение», «Простить остаток».
  4. Движения (выдача, погашения) списком.
  5. Напоминание.
- **Действия:**
  - «Добавить погашение» → сумма и счёт; если больше остатка — предупреждение «Это больше остатка на 2 000 ₸» с вариантами;
  - «Простить остаток» → подтверждение и выбор категории (FR-FIN-28).
- **Состояния:** закрыт (остаток 0) — плашка «Долг закрыт 20 октября».
- **База:** `Debt`, `Transaction` (тип «движение по долгу»), `Reminder`.
- **Задача пользователя / Фильтры / Доступность / Темы / Платформы:** — (общие правила).
- **Приёмка:** §6.7; AC-19; FR-FIN-26…28.

### SCR-42 Категории / SCR-43 Категория (К)
- **SCR-42:** переключатель «Расходы / Доходы»; дерево «категория → подкатегории» с иконками; «+ Новая категория»; «⋯ → Восстановить стандартные» (возвращает удалённые стандартные, свои не трогает); порядок кнопками «Выше / Ниже».
- **SCR-43:** название, иконка (сетка из набора), цвет (6 цветов + «Другое»), родитель, «Скрыть», итог за месяц и последние операции. «Удалить» → DLG-04 с выбором, куда перенести операции.
- **База:** `Category`.
- **Приёмка:** FR-FIN-12, 13; удаление категории с операциями невозможно без выбора переноса.

### SCR-44 Курсы валют (К)
- **Структура:** строки валют, которые есть в счетах: «USD — 470,50 ₸, от 20 октября», «EUR — нет курса» (красным). Нажатие → лист «1 USD = … ₸», дата (сегодня) → «Сохранить». История курсов валюты — на её экране.
- **Пустое состояние:** «Все счета в тенге — курсы не нужны».
- **База:** `ExchangeRate`.
- **Приёмка:** FR-FIN-15, 16; AC-17 (новый курс не меняет прошлые операции).

### SCR-45 Шаблоны (К)
Список шаблонов (иконка, название, сумма, счёт). Нажатие → применить (создаёт операцию) или «⋯ → Изменить / Удалить». Создаются из SCR-32 («Сделать шаблоном»). Пусто — «Сохраните частую трату как шаблон из экрана операции». FR-FIN-09.

### SCR-46 Импорт CSV
- **Цель:** перенести операции из другого трекера или таблицы без ручного ввода.
- **Задача пользователя:** загрузить файл из старого приложения и не получить дубликатов.
- **Структура (мастер из 5 шагов, сверху «Шаг 2 из 5»):**
  1. **Файл:** кнопка «Выбрать файл» → системный выбор. После выбора — имя, найденные кодировка и разделитель (можно изменить), первые 5 строк.
  2. **Колонки:** для каждого поля (Дата, Сумма, Тип, Категория, Счёт, Описание, Валюта) — выбор колонки файла; автоподстановка по заголовкам. Формат даты, правило знака суммы.
  3. **Категории и счета:** незнакомые значения из файла → «Создать» или «Сопоставить с…».
  4. **Проверка:** «Будет добавлено 480. Возможных дубликатов 20 — не будут добавлены». Список дубликатов с переключателями «добавить всё равно».
  5. **Итог:** «Импортировано 480 операций» и «Показать импортированные».
- **Данные:** содержимое файла (только в памяти и во временной папке), существующие операции для поиска дубликатов.
- **Действия:** «Далее» / «Назад» на каждом шаге. «Импортировать» на шаге 4 — сначала автобэкап, затем одна транзакция.
- **Фильтры:** —
- **Состояния:**
  - ошибка в строке — «Строка 300: сумма «12,5,0» не распознана. Ничего не импортировано» и «Изменить сопоставление» (AC-15);
  - неподдерживаемый файл — объяснение, какой формат нужен.
- **Переходы:** → SCR-31 (импортированные).
- **База:** `Transaction`, `Category`, `Account` — одной транзакцией; временный файл удаляется после операции (FR-SEC-06).
- **Доступность:** шаг озвучивается при переходе.
- **Темы / Платформы:** — (общие правила).
- **Приёмка:** AC-15, AC-21; FR-FIN-38, 39.

### SCR-47 Экспорт CSV (К)
Форма: период, фильтры (счета, категории), разделитель, «включать переводы». Кнопка «Экспортировать» → системное «Поделиться». Подпись: «Это таблица операций, а не резервная копия». FR-FIN-37, FR-BAK-12.

## 7. Заметки

### SCR-50 Заметки
- **Цель:** быстро найти или начать заметку.
- **Задача пользователя:** открыть конспект, найти список покупок.
- **Структура:**
  1. Заголовок «Заметки», справа «⋯» (Архив, Теги, Корзина, Сортировка).
  2. Строка поиска.
  3. Ряд чипов тегов (горизонтальная прокрутка, «Все» первым).
  4. Раздел «Закреплённые» (если есть).
  5. Список: заголовок (`callout` Semibold), первая строка текста (`footnote`, 1 строка), дата изменения справа («14:20», «вчера», «12 окт»). Без карточек — строки с разделителями, как в Notes.
- **Данные:** заметки (заголовок, начало текста, теги, закрепление, дата изменения).
- **Действия:**

| Элемент | Результат |
|---|---|
| Строка | → SCR-52 |
| Свайп / «⋯» | Закрепить, В архив, Удалить |
| Чип тега | Фильтр |
| «Добавить» | SCR-52, новая (с тегом, если фильтр активен) |

- **Фильтры:** тег, поиск по тексту; сортировка — по изменению (по умолчанию), созданию, названию.
- **Состояния:** пусто — «Здесь будут заметки. Например, конспект встречи или список покупок» и «Новая заметка».
- **Переходы:** → SCR-52, SCR-51, SCR-71, SCR-73.
- **База:** `Note`, `EntityTag` (чтение); закрепление и архив (запись).
- **Доступность / Темы / Платформы:** — (общие правила).
- **Приёмка:** FR-NOT-04; поиск по тексту ≤ 300 мс на 5 000 заметок.

### SCR-51 Архив (К → SCR-50)
Тот же список без закреплённых. Действия строки — «Вернуть», «Удалить». Пусто — «В архиве ничего нет».

### SCR-52 Заметка
- **Цель:** писать без отвлечений и связывать мысли с делами.
- **Задача пользователя:** записать конспект, превратить строку в задачу.
- **Структура:**
  1. «‹ Заметки», справа «⋯» и «Готово» (скрывает клавиатуру; появляется при редактировании).
  2. Текст на весь экран: первая строка — заголовок (`title2`), дальше `body`. Markdown показывается сразу оформленным: заголовки крупнее, чек-листы — кругами.
  3. Над клавиатурой — панель форматирования: Заголовок, Жирный, Список, Чек-лист, Ссылка на запись, Скрыть клавиатуру.
  4. Внизу текста (вне редактирования): теги и раздел «Связано» (задачи, операции, проекты) с «+ Связать».
- **Данные:** текст (Markdown-подмножество), теги, связи, даты.
- **Действия:**

| Элемент | Результат |
|---|---|
| Ввод | Автосохранение через ~1 с паузы (FR-NOT-05) |
| «Ссылка на запись» | SCR-74 → в тексте чип со ссылкой; нажатие на чип открывает запись |
| Выделить текст → «Создать задачу» | SH-04 с названием из выделения, задача связывается с заметкой |
| «⋯» | Закрепить, Теги, В архив, Экспорт .md («Поделиться»), Удалить |
| Чек-лист | Нажатие на круг отмечает пункт |

- **Фильтры:** —
- **Состояния:**
  - новая пустая заметка при выходе не сохраняется;
  - ошибка автосохранения — строка над текстом «Не удалось сохранить, текст в безопасности. Повторить»;
  - заметка в корзине — только чтение и «Восстановить».
- **Переходы:** → SCR-74, SH-04, связанные записи.
- **База:** `Note`, связи, `EntityTag`; черновик сохраняется локально при сворачивании и аварийном закрытии.
- **Доступность:** панель форматирования — кнопки с метками; чек-лист озвучивает состояние пункта.
- **Темы / Платформы:** — (общие правила).
- **Приёмка:** FR-NOT-01…06; после принудительного закрытия приложения текст не теряется (последние ~1 с допускается потерять, если ОС убила процесс до записи).

## 8. Голосовой ввод

### SCR-60 Запись
- **Цель:** надиктовать несколько записей подряд.
- **Задача пользователя:** сказать «завтра в 9 напомни…, потратил 3500…» и нажать «Готово».
- **Структура (полноэкранный лист):**
  1. «Отмена» слева. Справа — режим распознавания строкой `footnote`: «На устройстве» / «Через Apple» / «Через Google».
  2. Живой текст по мере распознавания (`title3`), если ОС его отдаёт.
  3. Индикатор звука: тонкая линия, реагирующая на громкость.
  4. Большая круглая кнопка «Готово» внизу по центру (`accent`).
  5. Подсказка под ней при первом использовании: «Можно сказать несколько дел и трат подряд».
- **Данные:** поток распознанного текста (в памяти, не сохраняется).
- **Действия:**

| Элемент | Результат |
|---|---|
| «Готово» / пауза ~5 с на Android | → SCR-61 с текстом |
| «Отмена» | Закрыть, ничего не сохраняется |

- **Фильтры:** —
- **Состояния:**
  - **первый запуск** — объяснение (USER_FLOWS §4.1) и системные разрешения;
  - **нет разрешения** — «Нужен доступ к микрофону» и «Открыть настройки», «Ввести текстом»;
  - **распознавание недоступно** — «Распознавание сейчас недоступно» и «Ввести текстом» (→ SCR-61 с пустым полем);
  - **прерывание** (звонок) — сразу SCR-61 с тем, что успели распознать.
- **Переходы:** → SCR-61.
- **База:** —
- **Доступность:** при включённом VoiceOver или TalkBack запись стартует по двойному нажатию на «Начать запись», чтобы озвучка не попала в микрофон [П].
- **Темы:** — (общие правила).
- **Платформы:**
  - iOS — on-device, если доступен, и если включено «Только на устройстве»;
  - Android — системный распознаватель; если его нет — сразу ввод текстом.
- **Приёмка:** FR-VOI-01, 02, 10; аудио нигде не сохраняется.

### SCR-61 Распознанный текст
- **Структура:**
  1. «Отмена» — «Проверьте текст».
  2. Редактируемое поле с текстом (`body`).
  3. Кнопки «Записать ещё» (дописывает) и основная «Разобрать».
- **Действия:**
  - «Разобрать» → SCR-62;
  - «Отмена» → закрыть без сохранения; если текст правили — подтверждение.
- **Состояния:** пусто — «Ничего не услышал», «Попробовать снова».
- **База:** при включённой настройке «История распознанных текстов» текст сохраняется в `VoiceSession` только после «Разобрать» (FR-VOI-10).
- **Цель / Задача пользователя / Данные / Фильтры / Переходы / Доступность / Темы / Платформы:** — (общие правила).
- **Приёмка:** FR-VOI-03.

### SCR-62 Подтверждение
- **Цель:** до сохранения ясно показать, что будет записано, и дать исправить.
- **Задача пользователя:** проверить три черновика, поправить одну дату, сохранить.
- **Структура (форма на `bgGrouped`):**
  1. «Отмена» — «Проверьте записи» — справа ничего; сохранение внизу.
  2. Строка «Распознанный текст» (свёрнута, раскрывается).
  3. **Группа на каждый черновик** (`surfaceGrouped`):
     - строка типа (иконка + «Задача» / «Расход» / «Доход» / «Перевод» / «Заметка» / «Долг»; нажатие — сменить тип) и кнопка удаления;
     - исходный фрагмент фразы `footnote` серым в кавычках;
     - поля типа строками формы: извлечённое — обычным текстом, подставленное по умолчанию — с подписью «по умолчанию», пустое — «не указано» серым;
     - **предупреждение** — строка с иконкой `warning` и текстом, под ней кнопки выбора («Сегодня, 23.10» / «Пт, 30.10»).
  4. «+ Добавить вручную».
  5. Закреплённая внизу основная кнопка «Сохранить всё (3)». Если есть блокирующая проблема — «Исправьте 1 запись» (нажатие прокручивает к ней).
- **Данные:** черновики (в памяти и во временной `VoiceDraft` на случай ошибки), справочники категорий и счетов для выбора.
- **Действия:**

| Элемент | Результат |
|---|---|
| Поле черновика | Правка на месте (тот же выбор, что в SH-02 / SH-04) |
| Тип | Смена без потери текста; поля перестраиваются |
| Кнопка удаления | Черновик скрыт, «Удалено · Отменить» |
| Кнопка варианта в предупреждении | Применяет вариант, предупреждение уходит |
| «Сохранить всё» | Все подтверждённые черновики одной транзакцией → SCR-63. Повторное нажатие во время сохранения игнорируется |
| «Отмена» | DLG-05 «Черновики не будут сохранены» |

- **Фильтры:** —
- **Состояния:**
  - ошибка сохранения — строка сверху «Не удалось сохранить, ничего не записано. Повторить», черновики на месте (AC-26);
  - ни одного черновика — «Не нашёл задач или трат» и кнопки «Править текст» / «Сохранить как заметку».
- **Переходы:** → SCR-63, назад к SCR-61.
- **База:** при сохранении — `Task`, `Transaction`, `Note`, `Debt`, `Reminder` одной транзакцией с ключом сессии (идемпотентность); `VoiceDraft` очищается.
- **Доступность:** каждый черновик — отдельная группа с заголовком «Черновик 1 из 3, задача»; предупреждения озвучиваются при появлении.
- **Темы / Платформы:** — (общие правила).
- **Приёмка:** AC-04, AC-05, AC-06, AC-26; FR-VOI-04…09, 11.

### SCR-63 Результат
- **Структура:** галочка в круге `positive`, «Сохранено», строка «3 задачи и 1 расход», список созданных записей (строки со ссылками), строка «Отменить» (5 с, удаляет созданное этой сессией), основная кнопка «Готово».
- **Действия:** строка → запись; «Готово» → экран, с которого начали.
- **База:** «Отменить» — мягкое удаление записей сессии одной транзакцией.
- **Цель / Задача пользователя / Данные / Фильтры / Состояния / Переходы / Доступность / Темы / Платформы:** — (общие правила).
- **Приёмка:** после «Отменить» в базе нет записей этой сессии, кроме журнала.

## 9. Общие экраны

### SCR-70 Поиск
- **Цель:** найти любую запись за секунды.
- **Задача пользователя:** «где та заметка про диплом», «сколько я платил за интернет».
- **Структура:**
  1. Поле поиска с фокусом и «Отмена».
  2. Без запроса — «Недавние запросы» (до 10, «Очистить»).
  3. С запросом — чипы типа (Все, Задачи, Операции, Заметки, Проекты, Цели, Привычки, Теги) и результаты группами по 3 с «Показать все N».
- **Данные:** полнотекстовый индекс по названиям, описаниям, текстам заметок, комментариям операций; суммы в разных написаниях.
- **Действия:** результат → экран записи; «Показать все» → полный список типа.
- **Фильтры:** тип.
- **Состояния:** ничего не найдено — «Ничего не найдено по «…»» и «Искать в корзине».
- **Переходы:** → экраны записей, SCR-73.
- **База:** поисковый индекс (FTS SQLite — решается на этапе 6); недавние запросы — локальная настройка без синхронизации.
- **Доступность:** количество результатов озвучивается.
- **Темы / Платформы:** — (общие правила).
- **Приёмка:** FR-GEN-03; NFR-PERF-05; «ё» = «е», регистр не важен; «3500» находит «3 500,00».

### SCR-71 Теги / SCR-72 Тег (К)
- **SCR-71:** строки «#учёба — 14». Действия: переименовать, объединить с другим (выбор), удалить (записи остаются без тега).
- **SCR-72:** записи с тегом группами по типам.
- **Приёмка:** FR-GEN-05.

### SCR-73 Корзина
- **Цель:** вернуть случайно удалённое или удалить навсегда.
- **Задача пользователя:** восстановить удалённую вчера задачу.
- **Структура:**
  1. «‹ Назад», «Корзина», справа «Очистить».
  2. Подпись «Записи удаляются навсегда через 30 дней» (срок из настроек).
  3. Группы по типам: строка записи + «удалено 22 окт, осталось 29 дней».
- **Данные:** мягко удалённые записи всех типов.
- **Действия:**

| Элемент | Результат |
|---|---|
| Свайп / «⋯» строки | Восстановить / Удалить навсегда (DLG-06) |
| «Очистить» | DLG-06 с числом записей → перед этим автобэкап |
| Строка | Просмотр только для чтения |

- **Фильтры:** тип записи.
- **Состояния:** пусто — «Корзина пуста».
- **Переходы:** → просмотр записи.
- **База:** `deleted_at` у всех сущностей; восстановление возвращает связи и пересоздаёт напоминания (F20).
- **Доступность / Темы / Платформы:** — (общие правила).
- **Приёмка:** FR-GEN-06; восстановление перевода возвращает обе части; окончательное удаление необратимо и требует подтверждения.

### SCR-74 Выбор связанной записи (К)
Лист с поиском и чипами допустимых типов (по матрице IA §6.1). Строка → связь создаётся, лист закрывается. Уже связанные отмечены галочкой (повторное нажатие удаляет связь).

### SCR-88 Резервные копии
- **Цель:** не потерять данные — сделать внешнюю копию и видеть, что автокопии работают.
- **Задача пользователя:** раз в неделю сохранить копию в «Файлы» или Telegram.
- **Структура:**
  1. **Статус** — выразительная деталь: «Внешний бэкап: 9 дней назад» крупно (`title3`; `warning`, если больше 14 дней), под ним «Автокопия на телефоне: сегодня, 21:40».
  2. Подпись `footnote`: «Копии на телефоне не защищают от его потери. Сохраняйте копию в другое место».
  3. Основная кнопка «Сохранить копию…».
  4. Строка «Восстановить из копии» → SCR-89.
  5. **Группа «Автокопии»:** частота (раз в день / после изменений), хранить последних (3–30, по умолчанию 7), список автокопий (дата, размер) с действиями «Поделиться», «Восстановить».
  6. **Группа «Защита»:** «Пароль для копий» (переключатель → DLG-09).
  7. Строка «Перенос на новый телефон» → SCR-90.
- **Данные:** `BackupMetadata` (даты, размеры, результат проверки), настройки автокопий.
- **Действия:**

| Элемент | Результат |
|---|---|
| «Сохранить копию…» | (Пароль, если включён) → создание и проверка файла (прогресс) → системное «Поделиться» / «Сохранить в Файлы». Успех → «Внешний бэкап: сегодня» |
| Пароль | DLG-09; пароль не запоминается |
| Автокопия → «Восстановить» | → SCR-89 с этим файлом |

- **Фильтры:** —
- **Состояния:**
  - нет места — «Не хватает места: нужно ~12 МБ», старые копии не тронуты;
  - копия не прошла проверку — «Копия повреждена и не сохранена. Повторить»;
  - автокопии не делались 3 дня — строка `warning` с причиной.
- **Переходы:** → SCR-89, SCR-90.
- **База:** читает всю базу (снимок), пишет `BackupMetadata`; файл формируется во временной папке и удаляется после передачи.
- **Доступность:** статус озвучивается полностью, включая предупреждение.
- **Темы:** — (общие правила).
- **Платформы:**
  - iOS — `UIActivityViewController`;
  - Android — Sharesheet или «Сохранить как» через SAF.
  Обе платформы не всегда сообщают, куда сохранён файл: «внешний бэкап» засчитывается по успешному завершению диалога.
- **Приёмка:** FR-BAK-01…14; AC-11; NFR-PERF-06.

### SCR-89 Восстановление
- **Цель:** безопасно вернуть данные из файла.
- **Структура (пошагово на одном экране):**
  1. «Выбрать файл» (или файл уже передан из «Файлов» / Telegram / списка автокопий).
  2. Проверка — индикатор «Проверяем файл…».
  3. Сводка: «Копия от 23.10.2026, 21:40 · 1 240 записей · приложение 1.0.0».
  4. Пароль (если файл зашифрован).
  5. Предупреждение: «Все текущие данные (N записей) будут заменены. Перед этим мы сохраним страховочную копию».
  6. Кнопка «Восстановить» — с удержанием 1 с (DLG-07).
  7. Итог: «Восстановлено 1 240 записей», «Готово». После — запрос разрешения на уведомления, если есть напоминания.
- **Данные:** заголовок файла, сводка, текущий размер базы.
- **Действия:** см. структуру.
- **Состояния:**
  - повреждён — «Файл повреждён. Текущие данные не изменены» (AC-12);
  - новее приложения — «Копия сделана в более новой версии. Обновите приложение» (AC-13);
  - неверный пароль — «Неверный пароль», задержка после 5 попыток (AC-14).
- **Переходы:** → SCR-10 после восстановления.
- **База:** проверка → страховочная копия → атомарная замена файла базы → миграция, если файл старше → пересоздание уведомлений.
- **Доступность:** этапы озвучиваются; удержание кнопки имеет альтернативу — двойное подтверждение в диалоге для диктора.
- **Задача пользователя / Фильтры / Темы / Платформы:** — (общие правила).
- **Приёмка:** AC-11…14; FR-BAK-06…08; прерывание на любом шаге не портит текущие данные.

### SCR-91 Безопасность
- **Структура:**
  1. **Группа «Код-пароль»:** «Включить код» → ввод и повтор 4–6 цифр; «Сменить код».
  2. **Группа:** «Face ID / Отпечаток» (если устройство поддерживает), «Блокировать» (сразу / через 1 / 5 / 15 минут), «Скрывать содержимое в переключателе приложений».
  3. Подпись `footnote`: «Данные на телефоне всегда зашифрованы. Код защищает от того, кто возьмёт разблокированный телефон. Если забыть код, войти можно будет только удалив данные и восстановив их из копии».
- **Действия:** включение кода — двойной ввод; выключение — ввод текущего кода.
- **База:** код — медленный хеш с солью в защищённом хранилище (NFR-SEC-01).
- **Цель / Задача пользователя / Данные / Фильтры / Состояния / Переходы / Доступность / Темы:** — (общие правила).
- **Платформы:** «Скрывать содержимое» — на iOS размытие при уходе в фон; на Android — `FLAG_SECURE`, с пояснением «Скриншоты приложения будут недоступны».
- **Приёмка:** FR-SEC-02…04; AC-25.

### SCR-93 Данные
- **Структура:**
  1. Корзина → SCR-73.
  2. Срок хранения корзины (7 / 30 / 90 дней).
  3. Срок хранения журнала (3 / 12 / 24 месяца / без ограничения).
  4. **Экспорт:** «Операции в CSV» → SCR-47, «Заметки в Markdown» (архив `.zip` → «Поделиться»).
  5. Отдельной группой внизу, красным: «Удалить все данные» → DLG-08.
- **Действия:** «Удалить все данные» — двойное подтверждение и ввод слова «УДАЛИТЬ». Удаляются база, ключ, автокопии, временные файлы. Затем открывается онбординг.
- **База:** настройки сроков; удаление всего.
- **Цель / Задача пользователя / Данные / Фильтры / Состояния / Переходы / Доступность / Темы / Платформы:** — (общие правила).
- **Приёмка:** FR-GEN-06, FR-HIS-03, FR-SEC-05; после удаления в песочнице приложения не остаётся файлов с данными.

## 11. Диалоги

Содержание диалогов DLG-01…10 — INFORMATION_ARCHITECTURE §5. Общие правила:
- Заголовок — что произойдёт («Удалить 12 записей навсегда?»).
- Текст — последствие и обратимость («Это нельзя отменить»).
- Кнопки — глаголами: «Удалить навсегда» (`danger`) и «Отмена». Порядок и вид — системные.
- Для DLG-07 и DLG-08 — подтверждение удержанием или вводом слова. Для диктора есть альтернатива — второй диалог подтверждения.
