# U-Assistant — безопасность и приватность данных (этап 6)

> Статус: **черновик на согласование**. Дата: 23.10.2026.
> Основание: REQUIREMENTS FR-SEC-01…08, NFR-SEC-01…05; D-014; TECH_RESEARCH §6; BACKUP_AND_RESTORE.md.
> Здесь — модель угроз (что защищаем, от кого и как) и честный список того, от чего приложение **не** защищает.

---

## 1. Что защищаем

| Актив | Где | Чувствительность |
|---|---|---|
| Финансовые данные: суммы, счета, долги, контрагенты | База | Высокая |
| Задачи, заметки, цели, привычки | База | Высокая (личная информация) |
| Распознанный текст голосовых сессий | База (временно) | Высокая |
| Ключ шифрования базы | Keychain / Keystore | Критическая |
| PIN | Keychain / Keystore (как хеш) | Высокая |
| Внешние резервные копии | Вне приложения — где решил пользователь | Высокая |
| Технический журнал | Песочница приложения | Низкая (без содержимого по правилу) |

## 2. Модель угроз

| # | Угроза | Вероятность | Защищает ли приложение | Как |
|---|---|---|---|---|
| T1 | Посторонний берёт **разблокированный** телефон и открывает приложение | Средняя | **Да, если включён PIN** | Блокировка приложения, автоблокировка, скрытие содержимого в переключателе приложений |
| T2 | Кто-то подглядывает в переключатель приложений или делает скриншот экрана недавних | Средняя | **Да** (при включённой опции) | Размытие (iOS), `FLAG_SECURE` (Android) |
| T3 | Доступ к файлам приложения: облачный бэкап ОС, извлечение через компьютер, сервисный центр | Низкая–средняя | **Да** | База зашифрована; ключ с доступом «только это устройство» не уезжает в облачный бэкап ОС |
| T4 | Утечка внешнего файла копии (отправил не тому, потерял флешку) | Средняя | **Да, если копия с паролем**. **Нет**, если без пароля | AES-256-GCM + Argon2id; предупреждение при экспорте без пароля |
| T5 | Подбор пароля копии | Низкая | **Частично** | Argon2id делает перебор дорогим; слабый пароль всё равно подбирается — минимум 8 символов и индикатор сложности |
| T6 | Утечка через технический журнал или отчёты о сбоях | Низкая | **Да** | Логи без содержимого, отправки наружу нет (NFR-SEC-02) |
| T7 | Утечка голоса и сказанных сумм | Средняя | **Частично** | Аудио не сохраняется. Распознавание на устройстве, где возможно. **В сетевом режиме речь обрабатывает Apple или Google** — это раскрывается пользователю (FR-VOI-02, SCR-92) |
| T8 | Вредоносное приложение на телефоне без root / jailbreak | Низкая | **Да** | Песочница ОС + шифрование |
| T9 | Телефон с root / jailbreak, вредоносный код с полными правами | Низкая | **Нет** | Такой код может читать память работающего приложения и Keychain. Обнаружение root не делаем: оно легко обходится и даёт ложное чувство защиты |
| T10 | Злоумышленник знает PIN и держит телефон | Низкая | **Нет** | PIN — замок интерфейса, не криптография |
| T11 | Потеря или поломка телефона | Средняя | **Только при внешней копии** | Напоминания о внешнем бэкапе. Копии на самом телефоне не помогают |
| T12 | Забыт пароль копии | Средняя | **Нет** | Это свойство шифрования. Явное предупреждение (DLG-09) |
| T13 | Забыт PIN | Средняя | **Частично** | Вход только через удаление данных и восстановление из копии. Объясняется при включении PIN |
| T14 | Повреждение базы (сбой питания, ошибка) | Низкая | **Да** | WAL, транзакции, автокопии, SCR-03 |

> **Простыми словами.** Шифрование защищает данные, когда телефон выключен или файлы попали не в те руки. PIN защищает от того, кто взял разблокированный телефон. Ни то, ни другое не защищает от того, кто знает ваш PIN или взломал систему телефона. А от потери телефона защищает только копия, сохранённая где-то ещё.

## 3. Управление ключом базы

| Этап | Что происходит |
|---|---|
| Первый запуск | Генерируется 256-битный ключ криптостойким генератором (`Random.secure()`). Сохраняется в `flutter_secure_storage` |
| Параметры хранения на iOS | Keychain, доступность `first_unlock_this_device` — после первой разблокировки после перезагрузки, без переноса на другие устройства и в облачный бэкап [Факт: TECH_RESEARCH §6]. «После первой разблокировки», а не «только когда разблокирован» — иначе фоновые задачи (бэкап, действия из уведомлений) не смогут открыть базу |
| Параметры хранения на Android | Keystore через `flutter_secure_storage` 10+ (RSA OAEP + AES-GCM) [Факт] |
| Открытие базы | Ключ читается из хранилища → `PRAGMA key` в колбэке `setup` drift |
| Android Auto Backup | Отключён для базы и хранилища ключей: `android:allowBackup="false"` или правила исключения [Факт: иначе ключ не расшифруется на новом устройстве] |
| Перенос на другое устройство | Ключ **не переносится**. Данные переносятся только через `.uabk` (BACKUP_AND_RESTORE §3.2); при восстановлении база шифруется ключом нового устройства |
| Ключ потерян (сбой хранилища, переустановка) | База нечитаема → SCR-03 предлагает восстановить из внешней копии. Внутренние автокопии зашифрованы тем же ключом и тоже нечитаемы — отсюда настойчивость с внешним бэкапом |
| Удаление всех данных | Удаляются база, автокопии, временные файлы **и ключ** (FR-SEC-05) |
| Смена ключа (rekey) | В v1 не требуется. Механизм `PRAGMA rekey` есть на случай будущей необходимости |

## 4. PIN и биометрия
- **PIN** 4–6 цифр. Хранится только **хеш**: Argon2id (облегчённые параметры, ~200 мс) с солью 16 байт в защищённом хранилище (NFR-SEC-01). Сравнение — за постоянное время.
- **Попытки:** после 5 неверных — задержка 30 с, затем 1, 5, 15 минут. Счётчик хранится в защищённом хранилище, поэтому перезапуск приложения его не сбрасывает.
- **Биометрия** (`local_auth`) — способ быстро подтвердить того же человека. Успех просто снимает блокировку интерфейса; ключ базы от биометрии не зависит. Если биометрия в системе поменялась (добавлен новый отпечаток), приложение просит PIN [П].
- **Автоблокировка:** при уходе в фон запускается таймер (сразу / 1 / 5 / 15 минут); при возврате после таймаута показывается SCR-01.
- **Скрытие содержимого:**
  - iOS — размытый экран-заглушка в `sceneWillResignActive`;
  - Android — `FLAG_SECURE` (запрещает и скриншоты; объясняется в настройке).

## 5. Шифрование внешних копий
См. BACKUP_AND_RESTORE §8:
- AES-256-GCM;
- ключ из пароля через Argon2id, параметры в манифесте;
- пароль не хранится.

---

## 6. Временные файлы
- Создаются только в приватной временной папке приложения (`getTemporaryDirectory()`), никогда в общих папках.
- Расшифрованный снимок базы для экспорта существует только во время операции и удаляется сразу после передачи.
- При каждом запуске временная папка приложения очищается от файлов старше 1 часа (на случай сбоя посреди экспорта).
- Файлы импорта копируются системным выбором в приватную папку, после разбора удаляются.
- **iOS:** файлы приложения защищены классом Data Protection «до первой разблокировки» (по умолчанию) [Факт*].

## 7. Логи и диагностика
- Политика — ARCHITECTURE §10: никаких текстов, сумм, названий, контрагентов, распознанной речи.
- Ошибки пишутся как тип + ID записи. ID — это UUID: он ничего не говорит о содержимом.
- Экспорт журнала — только по действию пользователя, с подписью «В журнале нет ваших записей и сумм».
- Автоматическая проверка: unit-тест пытается залогировать объект операции и проверяет, что в файл попал только безопасный набор полей (AC-24).

---

## 8. Сеть
- Приложение само не делает сетевых запросов (NFR-NET-02). Нет аналитики, трекеров, отчётов о сбоях, рекламы.
- Единственный внешний обмен — системное распознавание речи, если оно работает в сетевом режиме. Его выполняет ОС, а не приложение.
- Шрифты, иконки и данные валют встроены.
- **Проверка:**
  - в Android-манифесте **нет** разрешения `INTERNET` [П — `speech_to_text` использует системный сервис; проверить, что плагину оно не нужно];
  - на iOS нет вызовов сетевых API в коде приложения (проверка при ревью зависимостей).

## 9. Разрешения

| Разрешение | Когда запрашивается | Без него |
|---|---|---|
| Уведомления | При первом напоминании (FR-REM-06) | Задачи сохраняются; напоминания не приходят, видна причина |
| Точные будильники (Android 12+) | При первом напоминании, после объяснения | Неточные напоминания |
| Микрофон + распознавание речи (iOS) | При первом нажатии на микрофон | Ввод текстом |
| Календарь (чтение) | При включении функции | Без событий телефона |
| Face ID | При включении биометрии | Только PIN |
| Хранилище | **Не запрашивается** | — (системный выбор файлов) |
| Интернет | **Не запрашивается** (§8) | — |

Тексты обоснований — на русском, конкретные (NFR-STORE-01). Например: «Микрофон нужен, чтобы вы могли продиктовать задачи и траты. Запись не сохраняется».

## 10. Приватность голосового ввода
- Аудио нигде не сохраняется. Приложение его даже не получает: системный распознаватель возвращает только текст.
- Режим распознавания всегда виден на экране записи. Есть настройка «Только на устройстве».
- Распознанный текст хранится:
  - пока сессия не завершена — для восстановления после сбоя;
  - после завершения — только при включённой «Истории распознанных текстов» (по умолчанию выключена).

## 11. Удаление данных
- **«Удалить все данные»** — база, WAL-файлы, автокопии, страховочные копии, временные файлы, журнал, ключ, PIN, настройки. Затем онбординг.
- **Удаление приложения ОС:** песочница удаляется системой. Элементы Keychain на iOS могут пережить удаление приложения [Факт*]. Поэтому при первом запуске без базы старый ключ из Keychain удаляется и создаётся новый.
- **Внешние копии**, которые пользователь сохранил сам, приложение удалить не может. Это сказано на экране удаления.

## 12. Требования магазинов (заранее)
- **Apple:**
  - privacy nutrition label — «Data Not Collected» [Вывод из §8];
  - `PrivacyInfo.xcprivacy` с причинами Required Reason API (дата файлов — для ротации копий, свободное место — для проверки перед бэкапом, UserDefaults — если используется плагинами);
  - строки разрешений.
- **Google Play:** Data safety — «данные не собираются и не передаются»; политика конфиденциальности (короткая страница на русском) обязательна даже в этом случае.

## 13. Проверки безопасности перед каждой вехой (чек-лист)
- [ ] В репозитории нет ключей, паролей, тестовых данных с реальными суммами.
- [ ] Новые зависимости проверены: лицензия, активность, нет ли сетевых вызовов и аналитики.
- [ ] Логи не содержат пользовательских данных (тест AC-24 зелёный).
- [ ] Android: `allowBackup` / правила исключения на месте; разрешения в манифесте — только из §9.
- [ ] Восстановление на другом устройстве работает (BACKUP_AND_RESTORE §13).
- [ ] Блокировка и скрытие содержимого работают на iPhone и эмуляторе.
