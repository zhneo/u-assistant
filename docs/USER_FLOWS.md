> Статус: **черновик на согласование**. Дата: 23.10.2026 (пятница — в примерах «сегодня» — это эта дата).

## 1. Принципы взаимодействия

| # | Принцип | Как применяется |
|---|---|---|
| P1 | **Разумные значения по умолчанию вместо вопросов** | Дата — сегодня. Счёт — последний использованный. Категория — последняя для этого типа. Время напоминания — 09:00. Пользователь меняет только то, что отличается |
| P2 | **Не выдумывать** | Ни форма, ни голос не заполняют поле, которого пользователь не задал и которое нельзя честно взять по умолчанию из P1. Голос **не применяет** P1 к дате задачи и сроку: если сказано «запиши задачу», срока нет |
| P3 | **«Отменить» вместо «Вы уверены?»** | Обратимые действия (удаление в корзину, выполнение, перенос, массовое изменение) выполняются сразу, со всплывающим «Отменить» на 5 с. Подтверждение спрашиваем только для необратимого: DLG-06…08 |
| P4 | **Мгновенный отклик** | Запись сохраняется локально и сразу видна в списке (≤ 100 мс, NFR-PERF-02). Короткая тактильная отдача при сохранении, выполнении задачи, отметке привычки. Отдача отключается системной настройкой |
| P5 | **Одно главное действие на экране** | Одна заметная кнопка. Второстепенное — текстовые кнопки и меню «⋯» |
| P6 | **Клавиатура не мешает** | В быстрых формах фокус сразу в главном поле. Кнопка «Готово» на клавиатуре сохраняет. Нижняя панель поднимается над клавиатурой, кнопка «Сохранить» всегда видна |
| P7 | **Жест = ускоритель, не единственный путь** | Свайп по строке (вправо — выполнить или подтвердить, влево — перенести или удалить) всегда дублируется меню «⋯» и экраном записи |
| P8 | **Ошибки объясняют три вещи** | Что случилось, сохранились ли данные, что делать. Без кодов ошибок и технических терминов |
| P9 | **Прогрессивное раскрытие** | Быстрая форма → «Подробнее» → полный экран. Редкие разделы появляются в «Обзоре», только когда в них есть данные (долги, накопления) |
| P10 | **Разрешения — в момент пользы** | Уведомления — при первом напоминании. Микрофон и распознавание — при первом нажатии на микрофон. Календарь — при включении функции. Перед системным запросом — экран-объяснение «зачем» с кнопками «Разрешить» и «Не сейчас» |
| P11 | **Безопасность данных видна** | Статус бэкапа на виду. Опасные действия описывают последствия числами: «будут заменены 1 240 записей» |

### Тон текстов [П]
- Обращение на **«вы»** со строчной буквы, коротко, без канцелярита и восклицательных знаков.
- Глаголы действия на кнопках: «Сохранить», «Перенести», а не «ОК».
- Числа с правильным склонением: «2 задачи», «5 задач».
- Без шуток в ошибках и в разделах про деньги и безопасность.

|---|---|---|

## 3. Потоки

Формат: **Триггер → Основной путь → Ветки → Результат в данных → Критерии приёмки.**
Нумерация шагов — нажатия и вводы пользователя. «Сист.» — реакция приложения.

### F01. Первый запуск (SCR-02)
- **Триггер:** приложение открыто впервые (база пуста).
- **Путь:**
  1. Экран «Базовая валюта»: KZT предвыбран, поиск по валютам → «Далее».
  2. «Создать счёт «Наличные»?» — сумма на руках (необязательно) → «Создать» / «Пропустить».
  3. «Ваши данные хранятся только на этом телефоне» — 3 пункта: без регистрации; делайте бэкап; бэкап можно сохранить куда угодно → «Начать».
- Сист.: открывается «Сегодня» с карточкой-подсказкой «Нажмите «+», чтобы записать первую трату или задачу» (скрывается после первой записи или крестиком).
- **Ветки:** выход из приложения на шаге 2 или 3 — при следующем запуске онбординг продолжается с шага 2 (валюта уже сохранена). Разрешения не запрашиваются (P10).
- **Данные:** настройка базовой валюты; опционально счёт «Наличные» с начальным балансом; категории по умолчанию (§6) создаются при первом запуске.
- **Приёмка:** онбординг занимает ≤ 3 экрана; от запуска до первой записанной траты ≤ 30 секунд.

### F02. Разблокировка (SCR-01)
- **Триггер:** запуск или возврат после таймаута автоблокировки при включённом PIN.
- **Путь:** если включена биометрия, системный запрос появляется сразу → успех → последний открытый экран. Иначе — ввод PIN.
- **Ветки:**
  - биометрия отменена или не распознана → PIN-клавиатура;
  - 5 неверных PIN подряд → задержка 30 с, затем растёт (1, 5, 15 мин);
  - «Забыли PIN?» → объяснение: сбросить можно только удалив данные и восстановив их из бэкапа → кнопка «Удалить данные и восстановить» (DLG-08) или «Назад»;
  - открытие из уведомления → после разблокировки открывается запись из уведомления.
- **Приёмка:** AC-25.

### F03. Быстрый расход (S1)
- **Путь:**
  1. «+».
  2. «Расход» → SH-02: фокус в сумме, клавиатура-калькулятор.
  3. Ввод «3500».
  4. «Сохранить» (или «Готово» на клавиатуре).
- Сист.: панель закрывается, всплывает «Расход 3 500 ₸ · Продукты · Наличные — Отменить», тактильный отклик. Операция видна в списках и итогах.
- **Варианты:**
  - другая категория — нажатие на чип (6 последних + «Все категории» → поиск по категориям);
  - другой счёт — нажатие на счёт → список счетов;
  - другая дата — чип «Сегодня» → «Вчера» / календарь;
  - калькулятор: «1200+850» → показывается «= 2 050», сохраняется результат;
  - «Подробнее» → полный экран (описание, теги, время, связь с задачей); введённые данные не теряются.
- **Ветки:**
  - нет ни одного счёта → вместо поля счёта — «Создать счёт «Наличные»» одним нажатием;
  - сумма пустая или 0 → «Сохранить» неактивна, подсказка «Введите сумму»;
  - счёт в валюте без курса → сохранение разрешено; в итогах пометка «нет курса USD» (F22);
  - закрытие свайпом с введённой суммой → «Отменить ввод?» («Удалить» / «Продолжить»).
- **Данные:** 1 операция типа «расход».
- **Приёмка:** S1 — 3 нажатия + ввод; запись видна в списке ≤ 100 мс.

### F04. Доход (S2)
Как F03, но тип «Доход», свои 6 последних категорий. Вариант: «Возврат» (переключатель в «Подробнее») → выбор категории расхода (FR-FIN-10).

### F05. Перевод (S3)
- **Путь:**
  1. «+».
  2. «Перевод» → SH-03.
  3. «Откуда» (предвыбран последний счёт-источник).
  4. «Куда».
  5. Ввод суммы.
  6. «Сохранить».
- **Варианты:**
  - **разные валюты** → появляется второе поле «Зачислено» и строка «Курс: 1 USD = 470,50 ₸». Курс подставляется из последнего введённого, но вторую сумму можно исправить — тогда курс пересчитывается из сумм;
  - комиссия → «Подробнее» → «Комиссия» (отдельный расход со счёта-источника, категория «Комиссии»);
  - кнопка «⇅» меняет счета местами.
- **Ветки:**
  - «Откуда» = «Куда» → «Сохранить» неактивна, подсказка «Выберите разные счета»;
  - счёт «только отслеживать» в любой стороне → появляется обязательное поле «Категория» с пояснением «Такой перевод учитывается как расход» (или «как доход» для обратного направления) (§6.4).
- **Данные:** пара связанных записей (+ расход-комиссия, если есть).
- **Приёмка:** AC-01, AC-02, AC-03.

### F06. Задача на завтра с напоминанием (S4)
- **Путь:**
  1. «+».
  2. «Задача» → SH-04.
  3. Название.
  4. Чип «Завтра».
  5. Чип «Напомнить» → чип становится «Напомнить 09:00».
  6. «Сохранить».
- **Ветка «первое напоминание»:**
  1. Перед сохранением — экран-объяснение «Чтобы напомнить о задаче, нужны уведомления» → «Разрешить» → системный запрос.
  2. Разрешено → задача сохранена, напоминание запланировано.
  3. Отказано → задача сохранена без уведомления. Всплывает «Напоминание не сработает: уведомления выключены» со ссылкой в настройки. На задаче значок «колокольчик перечёркнут».
- **Ветка Android «точные будильники»:**
  1. При первом напоминании на Android 12+ без разрешения точных будильников — второе объяснение: «Без этого напоминание может прийти с опозданием до нескольких минут» → «Разрешить» (системный экран) / «Оставить так».
  2. При «Оставить так» напоминание ставится неточным, на экране «Надёжность напоминаний» (SCR-85) статус жёлтый (FR-REM-05).
- **Варианты:**
  - «Напомнить» повторно → выбор: «В момент задачи», «За 15 мин», «За 1 час», «Своё время», «Убрать»;
  - задача с временем («Завтра 14:00») → «Напомнить» ставит напоминание на 14:00.
- **Данные:** задача + напоминание + запланированное уведомление ОС.
- **Приёмка:** S4 — 5 нажатий + ввод; после отказа в разрешении задача сохранена, пользователь видит причину.

### F07. Перенос задачи (S5)
- **Путь:** строка задачи → свайп влево или «⋯» → «Перенести» → «Завтра» (варианты: Сегодня, Завтра, Выходные, След. неделя, Выбрать дату, Без даты).
- Сист.: задача уходит из текущего списка, всплывает «Перенесено на сб, 24 окт — Отменить». Напоминание сдвигается на столько же.
- **Ветка «повтор по расписанию»:** перед переносом — DLG-02: «Только эта задача» (исключение) / «Изменить расписание» (правило сдвигается) / «Отмена».
- **Ветка «повтор от даты выполнения»:** переносится без вопроса (как в Things).
- **Ветка «напоминание в прошлом»:** если после переноса время напоминания уже прошло (перенос на «Сегодня» с напоминанием на 09:00, а сейчас 14:00) — подсказка «Время напоминания прошло — выбрать новое?».
- **Приёмка:** S5 — 2–3 нажатия; напоминание переставлено (AC-07 по смыслу).

### F08. Повторяющаяся задача: выполнить, пропустить, приостановить
- **Выполнить:** чекбокс → задача зачёркивается, через 1 с уходит в «Выполненные». Сист. создаёт следующий экземпляр по правилу. Всплывает «Выполнено · следующая: пн, 26 окт — Отменить».
- **Пропустить:** «⋯» → «Пропустить этот раз» → экземпляр помечается «пропущено» → следующий экземпляр.
- **Приостановить или завершить серию:** экран задачи → «Повтор» → «Приостановить» / «Завершить серию» (с вопросом про текущий экземпляр: «оставить как обычную задачу» / «удалить»).
- **Ветка:** отмена «Выполнено» (через «Отменить») удаляет созданный следующий экземпляр и возвращает текущий.
- **Приёмка:** AC-08, AC-09, AC-10; после отмены нет лишнего экземпляра.

### F09. Отметка привычки (S11)
- **Путь:** «Сегодня» → кружок привычки → заполняется, счётчик серии +1, тактильный отклик.
- **Варианты:**
  - повторное нажатие снимает отметку;
  - отметка за прошедший день — экран привычки → календарь → день;
  - «N раз в неделю» — кружок показывает «2/3».
- **Ветка:** привычка на паузе — на «Сегодня» не показывается, серия не ломается.

### F10. Заметка (S6)
- **Путь:** «+» → «Заметка» → редактор, курсор в тексте → ввод → «Назад».
- Сист.: автосохранение при каждой паузе ввода; пустая заметка при выходе не сохраняется.
- **Варианты:**
  - панель форматирования: заголовок, жирный, список, чек-лист, ссылка на запись;
  - «Ссылка на запись» → SCR-74 → выбор задачи → в тексте появляется ссылка-чип;
  - выделить строку → «Создать задачу» → SH-04 с названием из выделения; задача связывается с заметкой.
- **Ветка:** ошибка автосохранения → баннер «Не удалось сохранить, текст в безопасности — повторить» (FR-NOT-05).

### F11. Голосовой ввод (S7)
Подробно — §4.
1. Микрофон («Сегодня» или «+» → «Голос»).
2. При первом использовании — объяснение и системные разрешения (микрофон, распознавание речи на iOS).
3. SCR-60: индикатор режима + живой текст → пользователь говорит → «Готово» (или авто-остановка по паузе).
4. SCR-61: текст, можно править → «Разобрать».
5. SCR-62: карточки черновиков → правки → «Сохранить всё (3)».
6. SCR-63: «Сохранено: 2 задачи, 1 расход» → «Готово» или переход к записи.

**Ветки:** §4.5.

### F12. Поиск (S8)
- **Путь:** иконка поиска → ввод «3500» или «такси».
- Сист.: результаты по группам появляются по мере ввода, сначала самые новые операции.
- **Варианты:**
  - чип типа («Операции») сужает результаты;
  - поиск суммы находит «3500», «3 500» и «3500,00»;
  - поиск без учёта регистра, «ё» = «е».
- **Пустой результат:** «Ничего не найдено по «…»» + «Искать в корзине».

### F13. Бюджет: проверить и создать (S9)
- **Проверить:** Финансы → Обзор → карточка бюджета (закреплённая) → SCR-37: «Потрачено 64 300 из 100 000 ₸ · осталось 35 700 · 8 дней · ~4 460 ₸ в день».
- **Создать:**
  1. Финансы → «⋯» → Бюджеты → «+».
  2. Категории (мультивыбор, подкатегории включаются автоматически).
  3. Лимит.
  4. Период (Месяц от дня зарплаты — из настройки).
  5. «Закрепить на обзоре» (вкл.).
  6. «Сохранить».
- **Ветки:**
  - категория уже в другом бюджете → предупреждение «Эта категория уже есть в бюджете «Еда»» (разрешено, но понятно);
  - 80% и 100% → уведомление (если включено).
- **Приёмка:** AC-18.

### F14. От графика к операциям (S10)
- **Путь:** Финансы → Аналитика → «Структура» → нажатие на сегмент «Транспорт».
- Сист.: сегмент выделяется, под диаграммой — «Транспорт · 42 500 ₸ · 18%» и кнопка «Операции (23)» → SCR-31 с фильтром «октябрь, Транспорт». Второе нажатие на сегмент сразу открывает список [П].
- **Варианты:**
  - подкатегории → «Транспорт» → «Такси», «Автобус»;
  - столбец в «Динамике» → операции этого дня или месяца.
- **Приёмка:** AC-20: сумма списка равна значению сегмента.

### F15. Плановый платёж: подтверждение
- **Триггер:** наступила дата регулярного платежа «Интернет 7 990 ₸».
- Сист.: уведомление (если включено) и счётчик «Ожидают подтверждения (1)» на «Сегодня» и «Обзоре».
- **Путь:** SCR-13 → «Подтвердить» (сумма редактируется, например пришло 8 490) → операция проведена.
- **Ветки:**
  - «Пропустить» — операции нет, правило идёт дальше;
  - «Перенести» — на выбранную дату;
  - правило «проводить автоматически» → операция создаётся сама в день платежа при открытии приложения, в журнале — «проведено автоматически».
- **Данные:** операция ссылается на правило.

### F16. Долг: дать в долг и получить возврат
- **Путь:**
  1. Финансы → «⋯» → Долги → «+».
  2. «Мне должны».
  3. Кому (текст).
  4. Сумма 15 000.
  5. Счёт «Карта».
  6. Срок (необязательно) → «Сохранить».
- **Возврат:** экран долга → «Добавить погашение» → 5 000 → счёт → «Сохранить». Остаток 10 000.
- **Ветки:**
  - погашение больше остатка → предупреждение «Это больше остатка на 2 000 ₸» с вариантами «Погасить полностью» / «Изменить сумму»;
  - «Простить остаток» → подтверждение и выбор категории расхода.
- **Приёмка:** AC-19.

### F17. Накопительная цель
- **Путь:**
  1. Дела → Цели → «+».
  2. Название «Ноутбук».
  3. Тип «Накопительная».
  4. Целевая сумма 500 000 ₸.
  5. Дата 01.03.2027.
  6. Счета: «Копилка» → «Сохранить».
- Сист.: экран цели: «Накоплено 120 000 из 500 000 ₸ (24%) · нужно ~95 000 ₸ в месяц».
- **Ветка:** нет подходящего счёта → «Создать счёт-копилку» прямо в форме.

### F18. Экспорт бэкапа (S12)
- **Путь:**
  1. «Сегодня» → ⚙ → «Резервные копии».
  2. «Экспортировать бэкап».
  3. Сист. создаёт и проверяет файл (прогресс) → системное меню «Поделиться».
  4. Пользователь выбирает «Сохранить в Файлы», Google Диск или Telegram.
- Сист.: при успешной передаче — «Внешний бэкап: сегодня». Если меню закрыто без выбора — статус не меняется.
- **Ветки:**
  - пароль включён → ввод пароля перед созданием (или сохранённый не запоминается — вводится каждый раз [П]);
  - нет места → «Не хватает места: нужно ~12 МБ» — текущие данные и старые копии не тронуты;
  - ошибка проверки файла → «Копия не прошла проверку и не сохранена — повторить».
- **Ограничение:** iOS и Android не всегда сообщают, куда сохранён файл. «Внешний бэкап» отмечается при успешном завершении системного диалога; это честно описано в справке [Гипотеза: поведение `share_plus` проверить на этапе 6].

### F19. Восстановление и перенос на новое устройство (S13)
- **Старое устройство:** F18 → файл в «Файлах», Google Диске, Telegram или на компьютере.
- **Новое устройство:**
  1. Установка → онбординг, шаг 1 содержит ссылку «Восстановить из бэкапа» (или Настройки → Резервные копии → «Восстановить»).
  2. Выбор файла (или открыть `.uabk` из Telegram или «Файлов»).
  3. Сист. проверяет → сводка: «Бэкап от 23.10.2026 · 1 240 записей · версия приложения 1.0.0».
  4. Пароль (если есть).
  5. DLG-07 (если на устройстве уже есть данные) → удержание кнопки.
  6. Сист. создаёт страховочную копию текущих данных → заменяет → «Восстановлено 1 240 записей».
  7. Сист. пересоздаёт уведомления по напоминаниям и просит разрешения (P10).
- **Ветки:**
  - повреждённый файл → AC-12;
  - новая версия формата → AC-13;
  - неверный пароль → AC-14, 5 попыток без блокировки, но с задержкой;
  - восстановление прервано (приложение закрыто) → при следующем запуске база в прежнем состоянии; при повреждении — SCR-03.
- **Приёмка:** AC-11; после восстановления напоминания запланированы.

### F20. Удаление, отмена, корзина
- Удаление записи → «В корзину» + «Отменить» (5 с).
- Корзина: SCR-73 → «Восстановить» (запись возвращается со связями и напоминаниями, если их время не прошло) / «Удалить навсегда» (DLG-06).
- **Ветка:** восстановление операции перевода восстанавливает обе части; восстановление задачи, чей проект удалён, — во «Входящие» с подсказкой.
- **Приёмка:** AC-07.

### F21. Импорт CSV
- **Путь:**
  1. Финансы → «⋯» → Импорт CSV → выбор файла.
  2. Сист. определяет кодировку и разделитель, показывает первые 5 строк.
  3. Сопоставление колонок (автоподстановка по заголовкам «Дата», «Сумма», «Категория»…).
  4. Формат даты и знак суммы («расход — отрицательные» / отдельная колонка типа).
  5. Сопоставление незнакомых категорий и счетов: «Создать» / «Сопоставить с …».
  6. Предпросмотр: «Будет добавлено 480 · возможных дубликатов 20 (не будут добавлены)» (можно отметить вручную).
  7. «Импортировать».
- Сист.: перед импортом — автобэкап (FR-BAK-01); импорт одной транзакцией; итог со ссылкой «Показать импортированные».
- **Ветки:** ошибка в строке → AC-15 (ничего не импортировано, указаны строка и причина); неподдерживаемый формат файла → объяснение.
- **Приёмка:** AC-15, AC-21.

### F22. Нет курса валюты
- **Триггер:** есть операции или счёт в валюте без курса к базовой.
- Сист.: общий баланс «≈ 1 250 000 ₸ · неполный» → нажатие → «Нет курса: USD» → «Указать курс» → поле «1 USD = … ₸», дата (сегодня) → «Сохранить» → итоги пересчитаны.
- Баннер на «Сегодня» — только если затронут блок «Деньги сегодня».
- **Приёмка:** AC-16, AC-17.

### F23. Надёжность напоминаний
- **Триггер:** отказ в разрешении, отзыв разрешения в настройках ОС, ограничение энергосбережения (Android).
- Сист.: при возврате в приложение статус пересчитывается. Если хуже, чем было, — баннер «Напоминания могут не прийти» → SCR-85.
- SCR-85: список проверок со статусом (зелёный / жёлтый / красный) и кнопкой исправления у каждой; ссылка на инструкцию для производителя телефона (Android).

### F24. Повреждение базы (SCR-03)
- **Триггер:** база не открывается при запуске.
- Сист.: «Не удалось открыть данные. Ваши резервные копии целы» → «Восстановить из автокопии от 22.10.2026 21:40» (рекомендуется) / «Восстановить из файла» / «Начать с нуля» (DLG с удержанием, повреждённый файл сохраняется отдельно для диагностики).
- **Приёмка:** приложение не падает в цикле и не стирает данные без явного выбора.

### F25. Включение системного календаря
- **Путь:** «Сегодня» → подсказка «Показывать события из календаря телефона?» (один раз, можно закрыть) или Настройки → Дела и календарь → «События календаря телефона» → объяснение → системное разрешение → выбор календарей (по умолчанию все).
- Сист.: события показываются в «Сегодня» и календаре с отдельным стилем и подписью календаря; нажатие открывает системный календарь.
- **Ветки:** отказ → функция выключена, подсказка в настройках. Отзыв разрешения → блок исчезает без ошибок.
- **Приёмка:** AC-22.

## 4. UX голосового ввода

### 4.1 Режим и приватность
- Перед первым использованием — экран: «Речь распознаёт система телефона. На iPhone это может происходить на устройстве; иначе запись обрабатывает Apple или Google. U-Assistant не хранит аудио».
- На SCR-60 всегда виден значок режима: «На устройстве» / «Через Apple» / «Через Google».
- Настройка «Только на устройстве»: если недоступно — микрофон показывает «Недоступно без сети» и предлагает ввести текст.

### 4.2 Как разбивать фразу на записи
Стартовые правила [П]. Финальные правила определяются тестами на корпусе (§4.6).

| Сигнал | Пример | Действие |
|---|---|---|
| Конец предложения (точка, пауза, если ОС ставит пунктуацию) | «…руководителю. Сегодня потратил…» | Граница записи |
| Связки «ещё», «также», «а ещё», «и ещё», «потом» в начале части | «Ещё запиши, что…» | Граница записи |
| «и» между двумя глаголами-командами | «купить хлеб и позвонить маме» | Две задачи [П] |
| «и» внутри объекта | «купить хлеб и молоко» | Одна задача |
| Перечисление трат | «потратил 500 на такси и 2000 на обед» | Два расхода (у каждой суммы своя категория) |

### 4.3 Как определять тип
| Тип | Сигналы |
|---|---|
| Расход | «потратил», «заплатил», «купил за», «отдал», «оплатил» + сумма |
| Доход | «получил», «пришла зарплата», «заработал», «вернули» + сумма |
| Перевод | «перевёл с … на …», «снял с карты» (= перевод карта → наличные) |
| Задача | «напомни», «нужно», «надо», «запиши, что нужно», «не забыть», глагол в инфинитиве в начале |
| Заметка | «заметка», «запиши мысль», «запомни, что» без действия |
| Неизвестно | Ничего не подошло → карточка «Не понял, что это» с выбором типа; текст сохранён в поле названия или заметки |

Сумма без глагола («такси 1500») → расход с предупреждением «Это расход?» [П].

### 4.4 Карточка черновика (SCR-62)
- **Шапка:** иконка и тип (нажатие → смена типа без потери текста); исходный фрагмент фразы мелким шрифтом — чтобы было видно, откуда взялась запись.
- **Поля:** только относящиеся к типу. Извлечённое — обычный текст. Подставленное по P1 (счёт, дата расхода «сегодня») — с пометкой «по умолчанию». **Пустое — явная плашка «не указано»**.
- **Предупреждения** (жёлтая полоса с текстом, не только цветом):
  - «Дата неоднозначна: «в пятницу» — сегодня (23.10) или 30.10?» — два варианта кнопками;
  - «Категория не распознана» — чипы похожих категорий;
  - «Сумма не найдена»;
  - «Время напоминания прошло».
- **Блокирующие проблемы** (расход без суммы) не дают сохранить: «Сохранить всё» показывает «Исправьте 1 запись» и прокручивает к ней.
- **Действия:** изменить (раскрывает форму на месте), удалить (с «Отменить»), «+ Добавить вручную».
- **Порядок карточек** — как в речи.

### 4.5 Ветки ошибок голоса
| Ситуация | Что видит пользователь | Данные |
|---|---|---|
| Нет разрешения на микрофон или распознавание | Объяснение + «Открыть настройки» + «Ввести текстом» | — |
| Распознавание недоступно (нет сети, нет сервиса Google) | «Распознавание сейчас недоступно» + «Ввести текстом» | — |
| Пустой результат (тишина) | «Ничего не услышал» + «Попробовать снова» | — |
| Сеанс прервался (звонок, сворачивание) | Текст до прерывания сохранён на SCR-61 | Текст в памяти сессии |
| Не найдено ни одной записи | «Не нашёл задач или трат» + «Править текст» / «Сохранить как заметку» | — |
| Ошибка сохранения | SCR-62 остаётся, «Не удалось сохранить, ничего не записано — повторить» | Ничего (атомарно) |
| Отмена с черновиками | DLG-05 | Ничего |

## 5. Экран «Сегодня»: компоновка и плотность

Порядок блоков (сверху вниз), пустые блоки скрываются:

| # | Блок | Макс. строк до «Показать все» | Скрывается, когда |
|---|---|---|---|
| 1 | Дата + полоса недели | — | никогда |
| 2 | Баннер состояния (1) | 1 | нет проблем |
| 3 | Деньги сегодня: «Свободно до конца периода», траты сегодня, «Ожидают (N)» | 1 карточка | нет счетов |
| 4 | Просроченные | 3 (свёрнуто, если > 3) | нет просроченных |
| 5 | Задачи на сегодня | 7 | нет задач |
| 6 | Привычки | горизонтальный ряд | нет привычек |
| 7 | События календаря телефона | 5 | выключено или нет событий |
| 8 | Предстоящие платежи (7 дней) | 3 | нет платежей |

- Пользователь может скрыть блоки 3, 6, 7, 8 (Настройки → «Экран «Сегодня»») [П].
- **Проверка гипотезы H2** на прототипе: экран с типичным днём (2 просроченных, 6 задач, 3 привычки, 2 события, 2 платежа) должен читаться за ≤ 5 секунд. Главное действие дня должно быть видно без прокрутки на iPhone SE. Если не проходит — платежи переносятся в «Деньги сегодня» одной строкой.

## 7. Каталог состояний

Каждый экран со списком или данными проектируется для всех применимых состояний (детали — в UI_SPECIFICATION на этапе 5).

| Состояние | Правило | Пример |
|---|---|---|
| **Пусто (впервые)** | Что здесь будет + одно действие + пример | «Здесь будут операции. Запишите первый расход» |
| **Пусто (после фильтра)** | Что отфильтровано + «Сбросить фильтры» | «Нет операций за ноябрь в «Такси»» |
| **Загрузка** | Локальные данные — без индикаторов, если < 300 мс; дольше — скелетон на месте контента | Аналитика за год на большой базе |
| **Длительная операция** | Прогресс с описанием шага; интерфейс не блокируется, если операцию можно продолжить в фоне | Бэкап, импорт, восстановление |
| **Частичные данные** | Значение + пометка, что неполно, + действие | «Неполный итог: нет курса EUR» |
| **Нет разрешения** | Что не работает + зачем разрешение + «Открыть настройки» | Микрофон, уведомления, календарь |
| **Офлайн** | Только для голоса в сетевом режиме: «Нужна сеть» + «Ввести текстом» | — |
| **Ошибка действия** | Что случилось + сохранены ли данные + повтор | «Не удалось сохранить. Ничего не записано — повторить» |
| **Ошибка экрана** | Экран не может показать данные: объяснение + «Повторить» + «Сообщить» (экспорт тех. журнала) | Сбой запроса к базе |
| **Опасное действие** | Последствия числами + явная кнопка + удержание для самых опасных | DLG-07, DLG-08 |
| **Успех** | Всплывающее сообщение с кратким итогом и «Отменить» или «Открыть» | «Сохранено: 2 задачи, 1 расход» |

## 8. Прототип

Чтобы проверить потоки до дизайна, собран **кликабельный черно-белый прототип** (wireframe) ключевых экранов:

- быстрые формы расхода и задачи;

Цвета, шрифты и стиль в нём намеренно нейтральные: проверяется структура, а не внешний вид.

**Ссылка:** https://claude.ai/artifact/Q3eKJPVoJK9qCYA7QzTmC4 (приватно; режим Play — переходы по ссылкам между экранами).
