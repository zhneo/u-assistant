# U-Assistant — голосовой ввод (этап 6б)

> Статус: **черновик на согласование**. Дата: 23.10.2026.
> Основание: мастер-промпт §6; REQUIREMENTS FR-VOI-01…13, AC-04…06, AC-26; USER_FLOWS §4 (UX, корпус фраз); UI_SPECIFICATION SCR-60…63; ARCHITECTURE §14; TECH_RESEARCH §3; D-001, D-006.
> Документ описывает **как устроен** голосовой ввод: распознавание, 10 этапов конвейера, модели данных, правила разбора русского языка, ошибки и тесты.

---

## 1. Границы и принципы
1. **Это не чат-бот.** Голос — ускоритель ввода. Всё, что можно сказать, можно сделать руками.
2. **Без внешних AI и без сервера.** Распознавание — системное (Apple / Google, по возможности на устройстве). Разбор текста — собственные правила на Dart (D-006).
3. **Ничего не выдумываем** (USER_FLOWS P2). Нет даты в речи — нет даты в черновике. Неоднозначно — предупреждение с вариантами, а не догадка.
4. **Ничего не сохраняется без подтверждения.** Подтверждённое сохраняется одной транзакцией и ровно один раз.
5. **Аудио не хранится никогда.** Распознанный текст — только пока сессия не завершена, или в истории, если пользователь её включил.
6. **Каждый этап конвейера тестируется отдельно** и не зависит от Flutter.

## 2. Распознавание речи (этапы 1–2)

### 2.1 Интерфейс
```dart
abstract interface class SpeechRecognizer {
  Future<RecognizerAvailability> availability(Locale locale); // onDevice / network / unavailable + причина
  Stream<RecognitionEvent> listen({required Locale locale, required bool onDeviceOnly});
  Future<void> stop();   // «Готово»
  Future<void> cancel(); // «Отмена»
}

sealed class RecognitionEvent { … }
// PartialText(text) — промежуточный текст для показа
// FinalText(text)   — итог
// SoundLevel(db)    — для индикатора
// RecognitionError(kind) — noPermission / unavailable / noSpeech / interrupted / network / unknown
```

**Реализации:**
- `SystemSpeechRecognizer` — через `speech_to_text` (TECH_RESEARCH §3.3);
- `FakeSpeechRecognizer` — для тестов: возвращает заданный текст и события;
- позже — `LocalModelRecognizer` (Vosk / sherpa-onnx) для полного офлайна и казахского (REQUIREMENTS §3.3).

### 2.2 Поведение платформ

| | iOS | Android |
|---|---|---|
| Движок | `SFSpeechRecognizer`, локаль `ru-RU` | Системный `SpeechRecognizer` (обычно Google) |
| На устройстве | `supportsOnDeviceRecognition` → `requiresOnDeviceRecognition = true`. Русский есть в списке on-device-диктовки Apple [Факт: TECH_RESEARCH §3.1] | API 33+: `checkRecognitionSupport` показывает, установлен ли офлайн-пакет `ru-RU` [Гипотеза: проверить на устройстве] |
| Ограничения | Сетевой режим — около 1 минуты на запрос и дневные лимиты [Факт] | Останавливается после паузы ~5 с, системные звуки не отключаются [Факт: README плагина] |
| Нет движка | — | Устройства без Google-сервисов: `unavailable` → ввод текстом |
| Разрешения | `NSMicrophoneUsageDescription`, `NSSpeechRecognitionUsageDescription` | `RECORD_AUDIO`; `<queries>` для `RecognitionService` |

### 2.3 Сессия записи
1. Проверка доступности → режим показывается на экране (SCR-60, FR-VOI-02).
2. Если включено «Только на устройстве», а on-device недоступен — запись не начинается; предлагается ввод текстом.
3. Длинная речь: на iOS при приближении к лимиту 1 минуты (сетевой режим) — подсказка «Нажмите «Готово» и продолжите новой записью». Кнопка «Записать ещё» на SCR-61 **дописывает** текст к уже распознанному.
4. Прерывание (звонок, сворачивание) → в SCR-61 попадает всё распознанное до прерывания.

## 3. Конвейер разбора (этапы 3–8, пакет `core/voice`)

```
String text
  │ 3. normalize()          → NormalizedText   (токены с позициями в исходном тексте)
  │ 4. segment()            → List<Utterance>  (фрагменты-высказывания)
  │ 5. classify()           → List<Classified> (тип + уверенность + признаки)
  │ 6. extract()            → List<Extracted>  (поля: сумма, дата, время, категория…)
  │ 7. validate()           → List<Checked>    (блокирующие проблемы, предупреждения)
  │ 8. buildDrafts()        → VoiceDrafts      (готово для экрана подтверждения)
  ▼
```

Каждая функция — **чистая**: одинаковый вход даёт одинаковый выход, без доступа к базе и часам. Контекст (сегодняшняя дата, часовой пояс, справочники категорий и счетов, словари пользователя) передаётся явно объектом `ParseContext`:

```dart
class ParseContext {
  final LocalDate today;           // из Clock
  final LocalTime now;
  final Weekday weekStart;
  final CurrencyCode baseCurrency;
  final List<AccountRef> accounts; // id, name, currency, isDefault
  final List<CategoryRef> categories;
  final SynonymDictionary synonyms;    // встроенный + пользовательский (FR-VOI-12)
  final LanguagePack lang;             // ru (позже kk)
}
```

> **Простыми словами.** Разбор — это конвейер из маленьких станков. Каждый делает одну операцию и передаёт деталь дальше. Если что-то разобрано неправильно, видно, на каком станке ошибка, и тест пишется именно для него.

### 3.1 Этап 3 — нормализация
**Вход:** сырой текст распознавателя. **Выход:** токены с привязкой к позициям исходного текста (чтобы показать «исходный фрагмент фразы» на карточке).

| Правило | Пример | Результат |
|---|---|---|
| Нижний регистр для анализа; оригинал хранится отдельно | «Завтра» | `завтра` |
| `ё → е` | «ещё» | `еще` |
| Числа прописью → число | «три тысячи пятьсот», «полторы тысячи», «тыщу двести», «две с половиной тысячи» | 3500, 1500, 1200, 2500 |
| Сокращения сумм | «3,5к», «3 тыс», «450 тысяч» | 3500, 3000, 450000 |
| Разделители в числах | «3 500», «3.500» (тысячи), «12 345,50» | 3500, 3500, 12345.50 |
| Валюта | «тенге», «тг», «₸», «доллар/долларов/$», «рубль/₽», «евро/€» | KZT, USD, RUB, EUR |
| Минорная часть | «… тенге 50 тиын», «20 долларов 30 центов» | дробная часть суммы |
| Время | «в девять утра», «в 9», «в 15:30», «в полдень», «в половине восьмого» | 09:00, 09:00*, 15:30, 12:00, 07:30* |
| Пунктуация распознавателя | точки и запятые | сохраняются как границы-подсказки |
| Слова-паразиты | «э-э», «ну», «короче», «типа» | удаляются из анализа (не из оригинала) |

\* «в 9» без «утра / вечера» и «в половине восьмого» — время неоднозначно. Правило: до 06:59 предлагаются варианты «утра / вечера»; от 07 до 11 по умолчанию — утро, с предупреждением, если до этого времени сегодня уже меньше 30 минут [П]. Точные правила закрепляются тестами корпуса.

### 3.2 Этап 4 — разбиение на высказывания
**Вход:** токены. **Выход:** список фрагментов (`Utterance`) с границами в исходном тексте.

Правила (из USER_FLOWS §4.2, в порядке применения):
1. Конец предложения (`.`, `!`, `?`, `;`) — граница.
2. Связки в начале части: «ещё», «также», «а ещё», «и ещё», «потом», «кроме того», «и запиши», «и напомни» — граница.
3. «и» между двумя **командами** («купить хлеб **и** позвонить маме») — граница, если справа от «и» стоит глагол в инфинитиве или в повелительном наклонении из словаря действий.
4. «и» внутри объекта («хлеб **и** молоко») — не граница.
5. Перечисление трат: «потратил 500 на такси **и** 2000 на обед» — граница перед каждой новой суммой с собственным «на …».

Словарь глаголов-действий (`lang/ru/verbs.dart`): купить, позвонить, написать, отправить, сдать, оплатить, забрать, записаться… — расширяется по мере роста корпуса.

### 3.3 Этап 5 — классификация
**Вход:** фрагмент. **Выход:** тип `task | expense | income | transfer | note | debt | unknown`, уверенность (0–1) и найденные признаки.

Метод — **взвешенные признаки** (без машинного обучения): у каждого признака есть вес для каждого типа; побеждает тип с наибольшей суммой.

| Признак | expense | income | transfer | task | note | debt |
|---|---|---|---|---|---|---|
| «потратил / заплатил / оплатил / купил за / отдал» | +3 | | | | | |
| «получил / пришла / заработал / вернули» + сумма | | +3 | | | | |
| «перевёл с … на …», «снял с карты» | | | +4 | | | |
| «дал в долг / занял / одолжил / вернул долг» | | | | | | +4 |
| «напомни / нужно / надо / не забыть / запиши, что нужно» | | | | +3 | | |
| Инфинитив в начале фрагмента | | | | +2 | | |
| «заметка / запиши мысль / запомни, что» без действия | | | | | +3 | |
| Есть сумма | +1 | +1 | +1 | −1 | −1 | +1 |
| Есть категория из словаря трат | +2 | | | | | |
| Есть дата или время | | | | +1 | | |

**Пороги:**
- победитель ≥ 3 и отрыв от второго ≥ 2 → уверенно;
- победитель ≥ 2, но отрыв < 2 → тип с предупреждением «Это расход?» (корпус №4);
- иначе → `unknown`: карточка «Не понял, что это» с выбором типа, текст сохраняется в названии.

Веса — стартовые [П]. Финальные значения подбираются по корпусу и закрепляются тестами. Изменение весов без прогона корпуса запрещено правилом CI (§9).

### 3.4 Этап 6 — извлечение полей
| Поле | Для типов | Правила | Чего **не** делаем |
|---|---|---|---|
| Сумма | expense, income, transfer, debt | Число из нормализации рядом с маркерами («за», «на», «потратил», валюта). Несколько сумм в одном фрагменте → предупреждение | Не берём числа из дат и времени («12 ноября», «в 9») |
| Валюта | те же | Явно названная. Иначе — валюта счёта по умолчанию, с пометкой «по умолчанию» | — |
| Дата операции | expense, income, transfer, debt | Явная («вчера», «12 октября»). Иначе — сегодня, с пометкой «по умолчанию» (разрешено P1: дата расхода по умолчанию — сегодня) | — |
| Дата задачи | task | Только явная: «сегодня», «завтра», «послезавтра», «в пятницу», «через 2 недели», «12 ноября», «в конце месяца» (= последний день, с предупреждением) | **Не ставим дату, если её не сказали** (корпус №1, задача 3) |
| Время | task | Явное (§3.1). «Утром / днём / вечером» — дата есть, времени нет, предупреждение «указать время?» (корпус №18) | Не превращаем «вечером» в 18:00 молча |
| Напоминание | task | Есть «напомни» + время → предлагается напоминание на это время. «Напомни» без времени → задача без напоминания и предупреждение (FR-VOI-11) | — |
| Повтор | task | «каждый понедельник», «каждый день», «по будням», «каждое 26 число» → `rrule` (DATABASE §7) | — |
| Категория | expense, income | Словарь синонимов (USER_FLOWS §6 + пользовательский) по словам фрагмента; совпадение с названием категории или подкатегории. Ничего не нашли → пусто + «Категория не распознана» с чипами 3 частых | Не ставим «Другое» молча |
| Счёт | денежные | Названный («с карты», «наличными»). Иначе — счёт по умолчанию (последний использованный) с пометкой | — |
| Счета перевода | transfer | «с X на Y» по названиям и типам счетов («карта», «наличные») | — |
| Название задачи | task | Фрагмент без служебных слов («напомни», «нужно», «запиши, что», даты и времени); первая буква — заглавная | — |
| Текст заметки | note | Фрагмент без «запомни, что / заметка» | — |
| Контрагент и направление долга | debt | «дал в долг Ерлану» → мне должны, Ерлан; «занял у …» → я должен | — |

**Относительные даты** (по `ParseContext.today`):

| Выражение | Правило | Неоднозначность |
|---|---|---|
| «в пятницу», когда сегодня пятница | Варианты: сегодня / через неделю | Да (корпус №7) |
| «в пятницу», когда сегодня вторник | Ближайшая пятница | Нет |
| «на следующей неделе» | Понедельник следующей недели, с пометкой | Предупреждение «уточнить день?» |
| «через N дней / недель / месяцев» | Арифметика дат в `core` | Нет |
| «12 ноября» | Ближайшее будущее 12 ноября (этот или следующий год) | Если дата прошла меньше недели назад — варианты «12 ноября прошедшее / следующего года» для операций |
| «в конце месяца» | Последний день текущего месяца | Предупреждение |

### 3.5 Этап 7 — проверка
| Проблема | Вид | Блокирует сохранение? |
|---|---|---|
| Расход, доход или долг без суммы | Ошибка | Да (корпус №16) |
| Перевод без одного из счетов или с одинаковыми счетами | Ошибка | Да |
| Валюта суммы не совпадает ни с одним счётом | Предупреждение «Нет счёта в USD» + выбор счёта | Да, пока счёт не выбран |
| Неоднозначная дата или время | Предупреждение с вариантами | Нет (без выбора дата остаётся пустой) |
| Категория не распознана | Предупреждение с чипами | Нет для `income`; для `expense` — сохраняется как «Без категории» только после явного выбора [П] |
| Время напоминания уже прошло | Предупреждение | Нет |
| Тип угадан с низкой уверенностью | Предупреждение «Это расход?» | Нет |

### 3.6 Этап 8 — черновики
```dart
sealed class Draft {
  final String id;              // локальный, для карточки
  final TextSpan source;        // фрагмент исходного текста
  final List<Issue> issues;     // ошибки и предупреждения
  final Set<String> defaulted;  // поля, подставленные по умолчанию
}
class TaskDraft extends Draft { String title; LocalDate? date; LocalTime? time; String? rrule; ReminderDraft? reminder; String? projectId; }
class TransactionDraft extends Draft { TxKind kind; Money? amount; String? accountId; String? toAccountId; String? categoryId; LocalDate date; String? note; }
class NoteDraft extends Draft { String body; }
class DebtDraft extends Draft { DebtDirection direction; String counterparty; Money? amount; String? accountId; LocalDate date; }
class UnknownDraft extends Draft { String text; }
```

Черновики сериализуются в JSON и сохраняются в `voice_session.drafts_json` при каждом изменении на экране подтверждения (DATABASE §4.23). После сбоя или закрытия приложения ничего не теряется (FR-VOI-09).

## 4. Подтверждение и сохранение (этапы 9–10)
- **Этап 9 — экран SCR-62** (UI_SPECIFICATION): правка, смена типа, удаление, «+ Добавить вручную». Смена типа пересобирает черновик из исходного фрагмента функцией `extract()` для нового типа — правила те же.
- **Этап 10 — сценарий `SaveVoiceSession(sessionId)`:**
  1. Открывается транзакция.
  2. Проверка `voice_session.status = 'draft'`. Иначе — выход без действий: повторное нажатие или двойной вызов ничего не дублирует (AC-04).
  3. Для каждого черновика вызывается обычный сценарий модуля-владельца: `AddTask`, `AddTransaction`, `AddTransfer`, `AddNote`, `AddDebt`. Голос не пишет в чужие таблицы напрямую (ARCHITECTURE §2). Каждая запись получает `voice_session_id`.
  4. `status = 'saved'`, `drafts_json = NULL`; `recognized_text = NULL`, если история выключена.
  5. Запись в журнал действий.
  6. Коммит, затем `ReminderScheduler.reconcile()`.
  - Любая ошибка → откат всей транзакции: ни одной записи, черновики на месте (AC-26).
- **«Отменить» на SCR-63** — мягкое удаление всех записей с этим `voice_session_id` одной транзакцией, затем `reconcile`.
- **«Отмена» на любом шаге до сохранения** — `status = 'cancelled'`, черновики и текст очищаются (AC-06).

## 6. Пользовательские словари (FR-VOI-12)
- Хранятся в `app_setting` (`voice_synonyms`: JSON «слово → id категории»).
- Пополняются:
  - вручную (SCR-87);
  - предложением после исправления [П]: пользователь сменил категорию черновика «магнум → Продукты» → строка «Запомнить: «магнум» — это Продукты?».
- Приоритет: пользовательский словарь → встроенный → совпадение с названием категории.

## 7. Приватность
DATA_SECURITY §10:
- аудио не сохраняется;
- режим распознавания всегда виден;
- текст хранится только во время сессии или в явно включённой истории;
- текст и черновики **никогда** не пишутся в технический журнал — только ID сессии и типы ошибок.

## 8. Ошибки
USER_FLOWS §4.5 и UI_SPECIFICATION SCR-60…62. Соответствие ошибок распознавателя и `AppFailure`:

| `RecognitionError` | Сообщение | Действие |
|---|---|---|

| unavailable | «Распознавание сейчас недоступно» | Ввести текстом |
| network (iOS, сетевой режим) | «Нужна сеть для распознавания» | Ввести текстом / повторить |

| interrupted | — (переход на SCR-61 с распознанным) | — |
| unknown | «Не получилось распознать» | Повторить / ввести текстом |

## 9. Тестирование и качество разбора

### 9.1 Тесты по этапам
| Этап | Тип тестов | Примеры |
|---|---|---|
| 3. Нормализация | Табличные unit-тесты «вход → выход» | 60+ вариантов чисел, валют, времени |
| 4. Разбиение | Табличные | Связки, «и» между командами и внутри объекта, перечисление трат |
| 5. Классификация | Табличные + отчёт по уверенности | Корпус по типам |
| 6. Извлечение | Табличные, с фиксированной `today` | Относительные даты на каждый день недели; конец месяца; високосный год |
| 7. Проверка | Unit | Каждая проблема §3.5 |
| 8. Черновики | Сериализация туда-обратно (JSON) | Все типы черновиков |
| 10. Сохранение | Сценарий с базой в памяти | AC-04 (двойное сохранение), AC-26 (ошибка посередине), AC-06 (отмена) |
| Распознаватель | Фейк + ручная проверка на iPhone и эмуляторе | Режимы, прерывания, ошибки |

### 9.2 Корпус фраз (сквозной тест)
- **Файл** `core/test/voice/corpus_ru.yaml`. Каждая запись — фраза, `today`, справочники и **ожидаемые черновики** полностью (тип, поля, предупреждения).
- **Старт** — 20 фраз из USER_FLOWS §4.6. **Цель к вехе M6** — 150+ фраз, включая собственные фразы владельца, собранные при использовании [П].
- **Метрика качества** — доля фраз, где черновики совпали полностью. Цель v1 — **≥ 80%** (гипотеза H3 из COMPETITOR_RESEARCH). Отдельно — **0 случаев выдуманных полей**: дата, сумма или категория появились без основания в тексте. Это жёсткое правило: такой тест не может быть «известной ошибкой».
- **CI** запускает корпус при каждом изменении `core/voice` и выводит метрику. Падение метрики ниже порога или любой случай «выдумки» — красная сборка.
- **Пример из мастер-промпта** (корпус №1 / AC-05) — отдельный именованный тест.

### 9.3 Производительность
Разбор фразы до 300 символов — ≤ 50 мс на эталонном Android [П]. Измеряется бенчмарком в `core`.
